🆚 Authentication vs Authorization
🔑 Authentication (Аутентификация)
  • Кто ты? — проверка личности
  • Логин + пароль → токен / сессия
  • Происходит один раз при входе
  • Пример: POST /api/auth/login
  • HTTP 401 Unauthorized — не аутентифицирован
  • Spring: AuthenticationManager.authenticate()
🛡 Authorization (Авторизация)
  • Что тебе можно? — проверка прав
  • Роли и полномочия (ROLE_ADMIN, READ_USERS)
  • Проверяется при каждом запросе
  • Пример: только ADMIN может DELETE /users
  • HTTP 403 Forbidden — нет прав
  • Spring: @PreAuthorize, hasRole()
⛓ SecurityFilterChain

Каждый HTTP-запрос проходит через цепочку фильтров Spring Security. Фильтры выполняются последовательно. Если один отклоняет запрос — следующие не вызываются.

Порядок фильтров
HTTP Request
    │
    ▼
SecurityContextPersistenceFilter  — восстанавливает SecurityContext из сессии/токена
    │
    ▼
UsernamePasswordAuthenticationFilter  — проверяет форму логина (если используется)
    │
    ▼
JwtAuthenticationFilter  ← наш кастомный фильтр (OncePerRequestFilter)
    │   • Читает токен из заголовка Authorization: Bearer <token>
    │   • Валидирует JWT
    │   • Устанавливает Authentication в SecurityContextHolder
    ▼
ExceptionTranslationFilter  — перехватывает 401/403 и возвращает правильный ответ
    │
    ▼
FilterSecurityInterceptor  — проверяет права доступа к ресурсу
    │
    ▼
Controller / Handler
💡 OncePerRequestFilter
Базовый класс для кастомных фильтров. Гарантирует выполнение ровно один раз на запрос (даже при forward/include внутри приложения). Всегда наследуй от него для JWT фильтра.
🪙 JWT — структура и принцип

JWT (JSON Web Token) — компактный, самодостаточный токен для передачи данных между сторонами. Состоит из трёх частей, разделённых точкой: header.payload.signature

ЧастьСодержимоеПример
HeaderАлгоритм подписи + тип токена{"alg":"HS256","typ":"JWT"}
PayloadClaims: sub, exp, iat, roles, + кастомные{"sub":"ivan","exp":1234,"roles":["ADMIN"]}
SignatureHMAC(base64(header)+"."+base64(payload), secret)SflKxwRJSMeKKF2QT4fwpM...
Стандартные Claims (поля Payload)
ClaimОписаниеТип
subSubject — кому выдан (username / userId)String
issIssuer — кто выдал (название сервиса)String
expExpiration — когда истекает (Unix timestamp)Long
iatIssued At — когда выданLong
jtiJWT ID — уникальный идентификатор токенаString
✅ Плюсы JWT
  • Stateless — не нужна сессия на сервере
  • Масштабируется — любой сервер проверит токен
  • Самодостаточный — содержит все нужные данные
  • Работает в микросервисах
⚠️ Минусы JWT
  • Нельзя отозвать до истечения (нет logout)
  • Payload виден всем (не шифруется, только подпись)
  • Не храни секреты в Payload!
  • При компрометации secret — все токены невалидны

👤 UserDetails и UserDetailsService

UserDetails — интерфейс Spring Security для объекта пользователя. UserDetailsService — интерфейс с одним методом loadUserByUsername(), который Spring вызывает при аутентификации.

Метод UserDetailsОписание

getAuthorities()Роли и права: ROLE_ADMIN, READ_USERS
isAccountNonExpired()Аккаунт не просрочен (обычно true)
isAccountNonLocked()Аккаунт не заблокирован
isCredentialsNonExpired()Пароль не просрочен

🎭 Roles и Authorities
Role (Роль)
  • Группа прав
  • Prefix ROLE_ обязателен в Spring Security
  • Пример: ROLE_ADMIN, ROLE_USER
  • hasRole("ADMIN") → ищет ROLE_ADMIN
  • Назначается пользователю целиком
Authority (Полномочие)
  • Конкретное право на действие
  • Без обязательного префикса
  • Пример: READ_USERS, DELETE_ORDERS
  • hasAuthority("READ_USERS")
  • Более гранулярный контроль
⚠️ ROLE_ префикс
hasRole("ADMIN") автоматически добавляет префикс и ищет ROLE_ADMIN.
hasAuthority("ROLE_ADMIN") ищет точное совпадение.
В getAuthorities() всегда возвращай ROLE_ с префиксом.
🔒 Method Security

Кроме настройки в SecurityFilterChain, можно защищать отдельные методы аннотациями. Включается через @EnableMethodSecurity.

АннотацияКогда проверяетсяПример
@PreAuthorizeДо выполнения метода@PreAuthorize("hasRole('ADMIN')")
@PostAuthorizeПосле выполнения (проверяет результат)@PostAuthorize("returnObject.owner == authentication.name")
@SecuredДо выполнения (устаревший, проще)@Secured("ROLE_ADMIN")
@RolesAllowedДо выполнения (JSR-250)@RolesAllowed("ADMIN")
@PreFilterФильтрует входную коллекцию@PreFilter("filterObject.owner == authentication.name")
@PostFilterФильтрует выходную коллекцию@PostFilter("filterObject.owner == authentication.name")
💡 SpEL выражения в @PreAuthorize
hasRole('ADMIN') — роль ADMIN
hasAnyRole('ADMIN','MODERATOR') — любая из ролей
hasAuthority('READ_USERS') — конкретное право
isAuthenticated() — просто аутентифицирован
authentication.name == #username — сравниваем с параметром метода
#user.id == authentication.principal.id — доступ к своим данным
✅ Best Practices и ошибки
✅ Best Practices
  • Всегда хэшируй пароли через BCrypt (factor ≥ 10)
  • Короткий срок жизни Access Token (15–60 мин)
  • Используй Refresh Token для обновления
  • Храни JWT secret в ENV, не в application.yml
  • HTTPS всегда — токен в заголовке виден при HTTP
  • Не храни секреты (пароли, карты) в JWT payload
  • DI через конструктор, не field injection в Security классах
  • Настраивай CORS явно — не разрешай все origins в prod
🚫 Частые ошибки
  • Хранить JWT в localStorage — XSS уязвимость
  • Длинный срок жизни токена (7+ дней) без refresh
  • Не валидировать exp и подпись токена
  • Разрешать все origins через cors().disable()
  • Отключать CSRF без понимания последствий
  • Возвращать стектрейс в 403/401 ответах
  • Хранить plain text пароли или MD5/SHA1
  • Забывать sessionManagement(STATELESS) при JWT

1. SecurityFilterChain — настройка правил доступа
Java
@Configuration
@EnableWebSecurity                                    // включаем Spring Security
@EnableMethodSecurity                                 // включаем @PreAuthorize и др.
public class SecurityConfig {

    private final JwtAuthFilter jwtAuthFilter;         // наш JWT фильтр
    private final UserDetailsService userDetailsService; // загрузка пользователя

    public SecurityConfig(JwtAuthFilter jwtAuthFilter,
                           UserDetailsService userDetailsService) {
        this.jwtAuthFilter = jwtAuthFilter;
        this.userDetailsService = userDetailsService;
    }

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            // ── CSRF отключаем для REST API (токены сами защищают)
            .csrf(csrf -> csrf.disable())

            // ── CORS настройка
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))

            // ── Управление сессиями: STATELESS для JWT
            .sessionManagement(session ->
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))

            // ── Правила доступа к endpoints
            .authorizeHttpRequests(auth -> auth
                // публичные endpoints — без токена
                .requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/api/public/**").permitAll()
                .requestMatchers("/actuator/health").permitAll()
                .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()

                // только ADMIN
                .requestMatchers(HttpMethod.DELETE, "/api/users/**").hasRole("ADMIN")
                .requestMatchers("/api/admin/**").hasRole("ADMIN")

                // аутентифицированные пользователи
                .anyRequest().authenticated()                  // всё остальное — с токеном
            )

            // ── Добавляем наш JWT фильтр ПЕРЕД стандартным фильтром аутентификации
            .addFilterBefore(jwtAuthFilter,
                UsernamePasswordAuthenticationFilter.class)

            // ── Обработчики 401 и 403
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint((req, res, e) -> {
                    res.setStatus(401);                          // 401 — не аутентифицирован
                    res.setContentType("application/json");
                    res.getWriter().write("{\"error\":\"Unauthorized\"}");
                })
                .accessDeniedHandler((req, res, e) -> {
                    res.setStatus(403);                          // 403 — нет прав
                    res.setContentType("application/json");
                    res.getWriter().write("{\"error\":\"Forbidden\"}");
                })
            )
            .build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder(12);             // factor 12 — хорошая защита
    }

    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();            // нужен для AuthController
    }

    @Bean
    public CorsConfigurationSource corsConfigurationSource() {
        CorsConfiguration config = new CorsConfiguration();
        config.setAllowedOrigins(List.of("http://localhost:3000")); // фронт
        config.setAllowedMethods(List.of("GET","POST","PUT","DELETE","PATCH"));
        config.setAllowedHeaders(List.of("*"));
        config.setAllowCredentials(true);
        UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
        source.registerCorsConfiguration("/**", config);   // для всех путей
        return source;
    }
}
2. JwtService — генерация и валидация токена
Java
// Зависимость в pom.xml:
// <dependency>
//   <groupId>io.jsonwebtoken</groupId>
//   <artifactId>jjwt-api</artifactId>
//   <version>0.12.3</version>
// </dependency>

@Service
public class JwtService {

    @Value("${app.jwt.secret}")
    private String secret;                                // секрет из ENV, не в коде!

    @Value("${app.jwt.expiration:86400000}")
    private long expiration;                              // мс, по умолч. 24 часа

    // ── Генерация ключа из секрета
    private SecretKey getSigningKey() {
        byte[] keyBytes = Decoders.BASE64.decode(secret);  // декодируем Base64 секрет
        return Keys.hmacShaKeyFor(keyBytes);               // создаём HMAC-SHA ключ
    }

    // ── Генерация JWT токена
    public String generateToken(UserDetails userDetails) {
        return generateToken(Map.of(), userDetails);        // без доп. claims
    }

    public String generateToken(
            Map<String, Object> extraClaims,              // дополнительные данные в токен
            UserDetails userDetails) {

        return Jwts.builder()
            .claims(extraClaims)                          // добавляем доп. claims
            .subject(userDetails.getUsername())           // sub = username
            .issuedAt(new Date(System.currentTimeMillis())) // iat = сейчас
            .expiration(new Date(                         // exp = сейчас + expiration
                System.currentTimeMillis() + expiration))
            .signWith(getSigningKey())                    // подписываем HMAC-SHA256
            .compact();                                   // собираем строку токена
    }

    // ── Извлечение username из токена
    public String extractUsername(String token) {
        return extractClaim(token, Claims::getSubject);    // sub claim = username
    }

    // ── Извлечение любого claim
    public <T> T extractClaim(String token,
            Function<Claims, T> claimsResolver) {
        final Claims claims = extractAllClaims(token);     // парсим все claims
        return claimsResolver.apply(claims);               // применяем функцию
    }

    // ── Парсинг всех claims из токена
    private Claims extractAllClaims(String token) {
        return Jwts.parser()
            .verifyWith(getSigningKey())                  // проверяем подпись
            .build()
            .parseSignedClaims(token)                     // парсим (кидает исключение при ошибке)
            .getPayload();                                 // возвращаем payload
    }

    // ── Валидация токена
    public boolean isTokenValid(String token, UserDetails userDetails) {
        final String username = extractUsername(token);    // достаём username из токена
        return username.equals(userDetails.getUsername()) // совпадает с пользователем
            && !isTokenExpired(token);                   // и токен не истёк
    }

    private boolean isTokenExpired(String token) {
        return extractExpiration(token).before(new Date()); // exp < сейчас
    }

    private Date extractExpiration(String token) {
        return extractClaim(token, Claims::getExpiration); // exp claim
    }
}
3. JwtAuthFilter — проверка токена в каждом запросе
Java
@Component
public class JwtAuthFilter extends OncePerRequestFilter { // один раз на запрос

    private final JwtService jwtService;
    private final UserDetailsService userDetailsService;

    public JwtAuthFilter(JwtService jwtService,
                          UserDetailsService userDetailsService) {
        this.jwtService = jwtService;
        this.userDetailsService = userDetailsService;
    }

    @Override
    protected void doFilterInternal(
            HttpServletRequest request,                   // входящий запрос
            HttpServletResponse response,                  // ответ
            FilterChain filterChain)                        // следующий фильтр
            throws ServletException, IOException {

        // ── 1. Читаем заголовок Authorization
        final String authHeader = request.getHeader("Authorization");

        // ── 2. Если нет заголовка или не Bearer — пропускаем (публичный endpoint)
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);      // передаём дальше
            return;
        }

        // ── 3. Извлекаем токен (убираем "Bearer ")
        final String jwt = authHeader.substring(7);        // "Bearer " = 7 символов

        try {
            // ── 4. Извлекаем username из токена
            final String username = jwtService.extractUsername(jwt);

            // ── 5. Если username есть и пользователь ещё не аутентифицирован
            if (username != null &&
                SecurityContextHolder.getContext().getAuthentication() == null) {

                // ── 6. Загружаем пользователя из БД
                UserDetails userDetails =
                    userDetailsService.loadUserByUsername(username);

                // ── 7. Проверяем валидность токена
                if (jwtService.isTokenValid(jwt, userDetails)) {

                    // ── 8. Создаём объект аутентификации
                    UsernamePasswordAuthenticationToken authToken =
                        new UsernamePasswordAuthenticationToken(
                            userDetails,                    // principal
                            null,                           // credentials (не нужны)
                            userDetails.getAuthorities()    // роли
                        );

                    // ── 9. Добавляем детали запроса
                    authToken.setDetails(
                        new WebAuthenticationDetailsSource().buildDetails(request));

                    // ── 10. Устанавливаем аутентификацию в SecurityContext
                    SecurityContextHolder.getContext()
                        .setAuthentication(authToken);     // теперь запрос аутентифицирован
                }
            }
        } catch (JwtException e) {
            // ── Невалидный токен — просто не устанавливаем аутентификацию
            // SecurityFilterChain сам вернёт 401
        }

        // ── 11. Передаём запрос следующему фильтру
        filterChain.doFilter(request, response);
    }
}

// ── Entity пользователя реализует UserDetails
@Entity
@Table(name = "users")
@Getter @Setter @Builder @NoArgsConstructor @AllArgsConstructor
public class User implements UserDetails {        // Spring Security интерфейс

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(unique = true, nullable = false)
    private String email;                           // используем как username

    private String password;                        // хэшированный BCrypt пароль

    @Enumerated(EnumType.STRING)
    private Role role;                              // ROLE_ADMIN, ROLE_USER

    private boolean enabled = true;               // активен ли аккаунт

    // ── Обязательные методы UserDetails
    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return List.of(new SimpleGrantedAuthority(role.name())); // ROLE_ADMIN
    }

    @Override
    public String getUsername() { return email; }  // email как логин

    @Override
    public boolean isAccountNonExpired()   { return true; }
    @Override
    public boolean isAccountNonLocked()    { return true; }
    @Override
    public boolean isCredentialsNonExpired(){ return true; }
    @Override
    public boolean isEnabled()             { return enabled; } // из поля
}

// ── UserDetailsService — загрузка пользователя при аутентификации
@Service
@RequiredArgsConstructor                               // Lombok: конструктор для final полей
public class UserDetailsServiceImpl implements UserDetailsService {

    private final UserRepository userRepository;

    @Override
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        return userRepository.findByEmail(username)          // ищем по email

                new UsernameNotFoundException("Пользователь не найден: " + username));
    }
}
5. AuthController — login endpoint
Java
// ── DTO запроса и ответа
public record LoginRequest(String email, String password) {}  // record = краткий DTO
public record AuthResponse(String token) {}                    // возвращаем токен
public record RegisterRequest(String email, String password, String name) {}

@RestController
@RequestMapping("/api/auth")
@RequiredArgsConstructor
public class AuthController {

    private final AuthService authService;            // бизнес-логика в сервисе

    @PostMapping("/login")
    public ResponseEntity<AuthResponse> login(
            @RequestBody @Valid LoginRequest request) {  // @Valid — валидируем
        return ResponseEntity.ok(authService.login(request));
    }

    @PostMapping("/register")
    public ResponseEntity<AuthResponse> register(
            @RequestBody @Valid RegisterRequest request) {
        return ResponseEntity.status(HttpStatus.CREATED)
            .body(authService.register(request));
    }
}

// ── AuthService — логика входа и регистрации
@Service
@RequiredArgsConstructor
public class AuthService {

    private final UserRepository      userRepository;
    private final PasswordEncoder      passwordEncoder;
    private final JwtService           jwtService;
    private final AuthenticationManager authManager;

    public AuthResponse login(LoginRequest request) {
        // authenticate() проверяет логин/пароль через UserDetailsService + BCrypt
        // кидает AuthenticationException если неверно
        authManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                request.email(),
                request.password()
            )
        );
        // если дошли сюда — аутентификация прошла
        User user = userRepository.findByEmail(request.email())
            .orElseThrow();
        String token = jwtService.generateToken(user);      // генерируем JWT
        return new AuthResponse(token);                     // возвращаем токен
    }

    public AuthResponse register(RegisterRequest request) {
        if (userRepository.existsByEmail(request.email())) {
            throw new EmailAlreadyExistsException(request.email());
        }
        User user = User.builder()
            .email(request.email())
            .password(passwordEncoder.encode(request.password())) // BCrypt хэш
            .role(Role.ROLE_USER)                              // роль по умолчанию
            .build();
        userRepository.save(user);
        return new AuthResponse(jwtService.generateToken(user)); // сразу выдаём токен
    }
}
6. @PreAuthorize — защита методов
Java
@RestController
@RequestMapping("/api/users")
@RequiredArgsConstructor
public class UserController {

    private final UserService userService;

    // ── Только ADMIN может видеть всех пользователей
    @GetMapping
    @PreAuthorize("hasRole('ADMIN')")                  // проверка ДО выполнения
    public List<UserResponse> getAllUsers() {
        return userService.findAll();
    }

    // ── Пользователь видит только свой профиль, ADMIN — любой
    @GetMapping("/{id}")
    @PreAuthorize("hasRole('ADMIN') or #id == authentication.principal.id")
    public UserResponse getUser(@PathVariable Long id) { // #id = параметр метода
        return userService.findById(id);
    }

    // ── Только ADMIN может удалять
    @DeleteMapping("/{id}")
    @PreAuthorize("hasRole('ADMIN')")
    public ResponseEntity<Void> deleteUser(@PathVariable Long id) {
        userService.delete(id);
        return ResponseEntity.noContent().build();          // 204 No Content
    }

    // ── Получить текущего пользователя из SecurityContext
    @GetMapping("/me")
    public UserResponse getCurrentUser(
            @AuthenticationPrincipal User currentUser) { // Spring инжектирует из контекста
        return userService.toResponse(currentUser);
    }

    // ── Программный доступ к SecurityContext
    public User getAuthenticatedUser() {
        return (User) SecurityContextHolder              // получаем контекст
            .getContext()
            .getAuthentication()                         // объект аутентификации
            .getPrincipal();                              // principal = наш User объект
    }
}
❓ Вопросы для собеседования
В чём разница между Authentication и Authorization?
What is the difference between Authentication and Authorization?
Easy▼
✅ Ответ
Authentication — «кто ты?». Проверка личности через логин/пароль или токен. Происходит один раз при входе. HTTP 401 при ошибке.
Authorization — «что тебе можно?». Проверка прав доступа к ресурсу. Проверяется при каждом запросе. HTTP 403 при отказе.
🔥 Пример
«Ты вошёл в систему (auth) — это аутентификация. Но у тебя нет роли ADMIN, поэтому ты не можешь удалить пользователя — это авторизация.»
Из чего состоит JWT? Что хранится в Payload?
What is the structure of JWT? What is stored in the Payload?
Medium▼
✅ Ответ
JWT состоит из трёх частей: Header (алгоритм подписи, тип), Payload (claims: sub, exp, iat + кастомные), Signature (HMAC(header+payload, secret)). Все части — Base64 encoded, разделены точкой. Payload не зашифрован — его видит любой. Никогда не храни пароли и секреты в Payload!
Как реализовать logout при использовании JWT?
How do you implement logout with JWT?
Hard▼
✅ Ответ
JWT stateless — токен нельзя «отозвать» просто так. Варианты: 1) Blacklist — хранить отозванные jti в Redis, проверять при каждом запросе. 2) Короткий TTL — access token 15 мин, refresh token в БД — logout удаляет refresh. 3) Версия пользователя — в JWT хранить tokenVersion, при logout увеличивать версию в БД — старые токены невалидны.
🔥 Лучший ответ
«Я использую связку: access token (15 мин, stateless) + refresh token (7 дней, в БД). Logout удаляет refresh token из БД. Access истекает сам через 15 мин. Для немедленного отзыва — Redis blacklist с TTL = оставшееся время жизни токена.»
Зачем нужен OncePerRequestFilter?
Why do we use OncePerRequestFilter for JWT?
Medium▼
✅ Ответ
Обычный фильтр может вызываться несколько раз на один HTTP запрос (при forward/include/error dispatch внутри приложения). OncePerRequestFilter гарантирует выполнение ровно один раз. Для JWT это критично — не нужно парсить и валидировать токен несколько раз.
Почему нельзя хранить JWT в localStorage?
Why shouldn't you store JWT in localStorage?
Medium▼
✅ Ответ
localStorage доступен через JavaScript — уязвим к XSS атакам. Если злоумышленник внедрит JS-код, он прочитает токен и получит полный доступ. Безопаснее хранить в HttpOnly Cookie — её нельзя прочитать через JS. Но тогда нужна защита от CSRF. Компромисс для SPA: access token в памяти (JS переменная), refresh token в HttpOnly cookie.
Как работает @PreAuthorize и SpEL в нём?
How does @PreAuthorize work and what is SpEL?
Medium▼
✅ Ответ
@PreAuthorize — AOP аннотация, перехватывает вызов метода до его выполнения. Использует SpEL (Spring Expression Language) для гибких выражений. В контексте доступны: authentication (текущий пользователь), #paramName (параметры метода), returnObject (для @PostAuthorize). Включается через @EnableMethodSecurity.
