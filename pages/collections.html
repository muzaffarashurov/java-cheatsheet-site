Схема
Iterable
  └── Collection
        ├── List
        │     ├── ArrayList       ← массив, быстрый get(i)
        │     ├── LinkedList      ← двусвязный список, быстрый add/remove в начале
        │     └── Vector          ← устаревший, thread-safe (избегай)
        │
        ├── Set
        │     ├── HashSet         ← хэш-таблица, O(1), без порядка
        │     ├── LinkedHashSet   ← HashSet + порядок вставки
        │     └── TreeSet         ← красно-чёрное дерево, O(log n), сортировка
        │
        └── Queue / Deque
              ├── PriorityQueue   ← min-heap, с приоритетом
              ├── ArrayDeque      ← быстрый стек и очередь (лучше Stack/LinkedList)
              └── LinkedList      ← реализует и List, и Deque

Map  (не наследует Collection!)
  ├── HashMap              ← хэш-таблица, O(1), порядок не гарантирован
  ├── LinkedHashMap        ← HashMap + порядок вставки / порядок доступа
  ├── TreeMap              ← красно-чёрное дерево, O(log n), сортировка по ключу
  ├── Hashtable            ← устаревший, thread-safe (избегай, бери ConcurrentHashMap)
  └── ConcurrentHashMap    ← потокобезопасный HashMap, O(1)
📋 List
ArrayList
  • Внутри — динамический массив Object[]
  • get(i) — O(1) ← главное преимущество
  • add в конец — O(1) амортизированный
  • add/remove в середине — O(n) (сдвиг)
  • Начальная ёмкость 10, растёт ×1.5
  • ✅ Используй по умолчанию для List
LinkedList
  • Внутри — двусвязный список (Node)
  • get(i) — O(n) ← главный минус
  • add/remove в начале/конце — O(1)
  • Больше памяти (каждый Node = 3 поля)
  • Реализует Deque — можно как стек/очередь
  • ✅ Используй только как Deque
💡 Совет
List.of(...) и Collections.unmodifiableList() создают неизменяемые списки. Попытка добавить элемент — UnsupportedOperationException.

🚦 Queue и Deque
Queue (FIFO)
  • offer(e) — добавить в конец (не кидает исключение)
  • poll() — взять из начала (null если пусто)
  • peek() — посмотреть начало (null если пусто)
  • PriorityQueue — минимальный элемент всегда первый
  • Используй ArrayDeque вместо LinkedList
Deque (стек + очередь)
  • push(e) / pop() — стек (LIFO)
  • offerFirst() / offerLast() — в начало/конец
  • pollFirst() / pollLast() — из начала/конца
  • ArrayDeque — самый быстрый, без null
  • ✅ Замени Stack на ArrayDeque
⚙️ HashMap — как работает изнутри

HashMap внутри — это массив «бакетов» (bucket[]). Каждый бакет — связный список (до Java 8) или сбалансированное дерево (с Java 8 при коллизиях).

Алгоритм put(key, value) — шаг за шагом ▼

1. Вычисляем hash = key.hashCode(), затем дополнительное перемешивание: hash ^ (hash >>> 16) — это уменьшает коллизии.

2. Определяем индекс бакета: index = hash & (capacity - 1) — быстрее, чем остаток от деления.

3. Если бакет пустой — кладём Node туда.

4. Если бакет занят (коллизия) — идём по цепочке, ищем ключ через equals(). Нашли — обновляем. Не нашли — добавляем в конец.

5. Если в одном бакете ≥ 8 элементов → цепочка превращается в красно-чёрное дерево (Java 8+). O(n) → O(log n).

6. Если заполнено > loadFactor (0.75) от capacity → resize: удваиваем массив, перехэшируем все элементы.

ПараметрЗначение по умолчаниюОписание
Initial capacity16Начальный размер массива бакетов
Load factor0.75При заполнении 75% — resize (удвоение)
Treeify threshold8При ≥8 коллизий в бакете — дерево
Untreeify threshold6При ≤6 — обратно в список
⚠️ Почему нельзя использовать мутабельные объекты как ключи
Если изменить поле объекта-ключа после помещения в Map — его hashCode изменится, и HashMap не найдёт элемент (будет искать в другом бакете). Ключи должны быть immutable (String, Integer, enum — идеальные ключи).

💻 Примеры кода
1. ArrayList — основные операции
Java
import java.util.*;

// ── Создание ArrayList
List<String> names = new ArrayList<>();    // пустой список
List<String> copy  = new ArrayList<>(names); // копия другого списка
List<String> fixed = List.of("Анна", "Борис"); // immutable (Java 9+), нельзя менять
List<String> mutable = new ArrayList<>(List.of("A", "B")); // изменяемая копия

// ── Добавление элементов
names.add("Иван");            // добавить в конец O(1)*
names.add(0, "Анна");          // добавить по индексу O(n) — сдвигает остальных
names.addAll(List.of("Пётр", "Мария")); // добавить коллекцию

// ── Доступ и изменение
String first = names.get(0);   // O(1) — быстрый доступ по индексу
names.set(0, "Алёна");          // заменить элемент по индексу

// ── Удаление
names.remove("Иван");           // удалить по значению O(n)
names.remove(0);                // удалить по индексу O(n)
names.removeIf(s -> s.startsWith("А")); // удалить по условию (Java 8+)

// ── Поиск
boolean has = names.contains("Пётр"); // O(n) — линейный поиск
int idx = names.indexOf("Пётр");     // индекс первого вхождения, -1 если нет

// ── Сортировка
Collections.sort(names);                      // по умолчанию — алфавит (Comparable)
names.sort(Comparator.reverseOrder());       // обратный порядок
names.sort(Comparator.comparingInt(String::length)); // по длине строки

// ── Итерация
for (String name : names) {             // for-each — самый простой способ
    System.out.println(name);
}
names.forEach(System.out::println);     // метод-ссылка (Java 8+)

// ── Преобразование
String[] arr = names.toArray(new String[0]); // List → массив
List<String> fromArr = Arrays.asList(arr);   // массив → List (фиксированный размер!)
2. HashMap — все важные операции
Java
// ── Создание Map
Map<String, Integer> scores = new HashMap<>();       // пустая карта
Map<String, Integer> fixed = Map.of("А", 1, "Б", 2);   // immutable (Java 9+)

// ── Добавление и обновление
scores.put("Иван", 95);           // добавить / перезаписать
scores.putIfAbsent("Иван", 80);   // добавит только если "Иван" ещё не существует

// ── Получение
int score = scores.get("Иван");              // 95, NPE если нет ключа
int safe  = scores.getOrDefault("Петя", 0); // 0 если нет — безопасно

// ── Проверки
boolean hasKey = scores.containsKey("Иван");    // O(1)
boolean hasVal = scores.containsValue(95);      // O(n) — медленно!

// ── Вычисление значений (Java 8+)
// computeIfAbsent — создаём список если ключа нет (группировка)
Map<String, List<String>> groups = new HashMap<>();
groups.computeIfAbsent("А", k -> new ArrayList<>()).add("Аня"); // создаёт и добавляет
groups.computeIfAbsent("А", k -> new ArrayList<>()).add("Артём"); // добавляет к существующему

// merge — удобен для счётчиков и агрегации
Map<String, Integer> wordCount = new HashMap<>();
for (String word : new String[]{"java", "java", "spring"}) {
    wordCount.merge(word, 1, Integer::sum);  // если нет — 1, если есть — прибавляем
}
// {java=2, spring=1}

// ── Итерация по Map (рекомендуемый способ)
for (Map.Entry<String, Integer> entry : scores.entrySet()) {
    System.out.println(entry.getKey() + " → " + entry.getValue()); // ключ и значение
}
scores.forEach((k, v) -> System.out.println(k + ": " + v)); // Java 8+, компактнее

// ── Работа с ключами и значениями
Set<String>      keys   = scores.keySet();   // все ключи (Set)
Collection<Integer> vals = scores.values();  // все значения (Collection)
3. Set — работа с уникальными элементами
Java
// ── HashSet — уникальность без порядка
Set<String> tags = new HashSet<>();
tags.add("java");    // добавляем тег
tags.add("spring"); // добавляем ещё
tags.add("java");   // дубль — игнорируется! Set остаётся {java, spring}
boolean added = tags.add("kafka"); // возвращает true если добавлен (не дубль)

// ── Операции над множествами
Set<Integer> a = new HashSet<>(Set.of(1, 2, 3, 4));
Set<Integer> b = new HashSet<>(Set.of(3, 4, 5, 6));

Set<Integer> union = new HashSet<>(a);
union.addAll(b);          // объединение: {1,2,3,4,5,6}

Set<Integer> intersect = new HashSet<>(a);
intersect.retainAll(b);   // пересечение: {3,4}

Set<Integer> diff = new HashSet<>(a);
diff.removeAll(b);         // разность: {1,2}

// ── TreeSet — автоматическая сортировка
TreeSet<Integer> sorted = new TreeSet<>(Set.of(5, 2, 8, 1));
System.out.println(sorted);            // [1, 2, 5, 8] — всегда отсортировано
System.out.println(sorted.first());    // 1 — минимальный элемент
System.out.println(sorted.last());     // 8 — максимальный
System.out.println(sorted.headSet(5)); // [1,2] — все < 5
System.out.println(sorted.tailSet(5)); // [5,8] — все >= 5

// ── LinkedHashSet — порядок вставки сохраняется
Set<String> ordered = new LinkedHashSet<>();
ordered.add("первый");   // порядок вставки
ordered.add("второй");
ordered.add("третий");
System.out.println(ordered); // [первый, второй, третий] — порядок сохранён
4. Streams + Collections — мощная комбинация
Java
import java.util.stream.*;

List<String> names = List.of("Иван", "Анна", "Иван", "Борис", "Анна");

// ── filter + collect → отфильтрованный список
List<String> startWithA = names.stream()
    .filter(s -> s.startsWith("А"))    // оставляем только начинающиеся с А
    .distinct()                          // убираем дубли
    .sorted()                            // сортируем
    .collect(Collectors.toList());      // собираем в список

// ── groupingBy → группировка по первой букве
Map<Character, List<String>> byLetter = names.stream()
    .distinct()
    .collect(Collectors.groupingBy(    // группируем
        s -> s.charAt(0)));             // по первому символу
// {И=[Иван], А=[Анна], Б=[Борис]}

// ── counting → подсчёт по группам
Map<String, Long> counts = names.stream()
    .collect(Collectors.groupingBy(
        s -> s,
        Collectors.counting()));         // {Иван=2, Анна=2, Борис=1}

// ── toMap → список в Map
List<User> users = getUsers();
Map<Long, User> userById = users.stream()
    .collect(Collectors.toMap(
        User::getId,                      // ключ
        u -> u,                            // значение
        (u1, u2) -> u1));                  // при дубле ключа — берём первого

// ── joining → объединить строки
String result = names.stream()
    .distinct()
    .collect(Collectors.joining(", ", "[", "]")); // "[Иван, Анна, Борис]"
❓ Вопросы для собеседования
Как работает HashMap изнутри?
How does HashMap work internally?
Hard▼
✅ Ответ
HashMap — массив бакетов. При put(k, v): 1) вычисляется hashCode ключа, 2) определяется индекс бакета, 3) при коллизии — список (Java 8+: дерево при ≥8 элементов), 4) при заполнении >75% — resize (удвоение). Поиск get(k): тот же хэш → бакет → equals по цепочке.
🔥 Сильный ответ
«В Java 8 добавили treeification: если в одном бакете накопилось ≥8 элементов, связный список превращается в красно-чёрное дерево. Это меняет худший случай с O(n) на O(log n). Это важно при плохой реализации hashCode, когда все объекты попадают в один бакет.»
В чём разница ArrayList и LinkedList?
What is the difference between ArrayList and LinkedList?
Easy▼
✅ Ответ
ArrayList — динамический массив: быстрый get(i) O(1), медленный add/remove в середине O(n). LinkedList — двусвязный список: медленный get(i) O(n), быстрый add/remove в начале/конце O(1). На практике ArrayList быстрее почти всегда из-за cache locality (данные в памяти подряд).
💡 Добавить
«LinkedList использовать как Deque — вот его реальный use-case. Как List — почти никогда, потому что даже add в середину ArrayList быстрее из-за System.arraycopy, оптимизированного на уровне JVM.»
Чем HashMap отличается от ConcurrentHashMap?
What is the difference between HashMap and ConcurrentHashMap?
Medium▼
✅ Ответ
HashMap не потокобезопасен — одновременная запись из нескольких потоков может привести к потере данных или бесконечному циклу. ConcurrentHashMap потокобезопасен: в Java 8 использует CAS-операции и блокировки на уровне бакета (не всей карты). Не допускает null ключи и null значения.
⚠️ Ошибка кандидата
Говорят «Hashtable потокобезопасен, можно использовать». Hashtable устарел — он блокирует всю Map на каждой операции, это намного медленнее ConcurrentHashMap.
Когда использовать TreeMap вместо HashMap?
When would you use TreeMap instead of HashMap?
Medium▼
✅ Ответ
TreeMap использовать когда нужна сортировка по ключу или навигационные операции: firstKey(), lastKey(), headMap(), tailMap(), subMap(). Стоимость: O(log n) вместо O(1). Пример: расписание по времени, прайс-лист по цене.
Что такое fail-fast итератор?
What is a fail-fast iterator?
Hard▼
✅ Ответ
Итераторы большинства коллекций (ArrayList, HashMap и др.) — fail-fast: если коллекция модифицируется структурно во время итерации не через сам итератор — бросается ConcurrentModificationException. Это быстрое обнаружение ошибки. Решение: использовать iterator.remove(), removeIf(), или CopyOnWrite коллекции.
