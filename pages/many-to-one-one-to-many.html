📌 Краткий конспект

Главное правило
В бидирекциональной связи @ManyToOne всегда владеет FK (owning side). @OneToMany — это зеркало (inverse side), которое управляется через mappedBy. Hibernate генерирует INSERT/UPDATE только на основе owning side!
АннотацияГде ставится?Что делает в БД?Default Fetch
@ManyToOneНа стороне "многих" (Product, CartItem)Создаёт столбец FK (напр. category_id)EAGER (⚠️ меняй на LAZY!)
@OneToManyНа стороне "одного" (Category, Cart)Ничего не создаёт (только читает данные)LAZY (✅ правильно)
@JoinColumnРядом с @ManyToOneНастраивает имя FK, nullable, unique—
mappedByРядом с @OneToManyУказывает имя поля во владельце связи—

📦 Реальные сущности (E-Commerce)

1. Category (1) ↔ (N) Product
Category.java (Inverse Side)
@Entity
@Table(name = "categories")
public class Category {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    // name: уникальное имя категории. length=100 ограничивает размер VARCHAR в БД
    @Column(nullable = false, unique = true, length = 100)
    private String name;

    /*
     * @OneToMany — ОБРАТНАЯ сторона связи (inverse side).
     * mappedBy = "category" ← ОБЯЗАТЕЛЬНО! Указывает на поле category в классе Product.
     * Без mappedBy Hibernate создаст ДВЕ связи (лишнюю таблицу или лишний FK).
     * 
     * cascade = {} ← НЕ ставь CascadeType.ALL здесь! Удаление категории не должно удалять товары.
     * fetch = LAZY ← Стандарт для коллекций. Загружает товары только при обращении.
     */
    @OneToMany(mappedBy = "category", 
              fetch = FetchType.LAZY)
    private List<Product> products = new ArrayList<>();
}
Product.java (Owning Side)
@Entity
@Table(name = "products")
public class Product {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 255)
    private String name;

    // precision=10, scale=2 → DECIMAL(10,2) в БД. Безопасно для денег!
    @Column(nullable = false, precision = 10, scale = 2)
    private BigDecimal price;

    /*
     * @ManyToOne — ВЛАДЕЛЕЦ связи (owning side).
     * Именно здесь Hibernate создаст столбец category_id в таблице products.
     * 
     * fetch = LAZY ← Всегда меняй EAGER на LAZY для @ManyToOne в реальных проектах!
     * EAGER грузит категорию всегда → N+1 проблема при списках товаров.
     */
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "category_id", nullable = false)
    private Category category;
}
2. Cart (1) ↔ (N) CartItem ↔ (N) Product
Cart.java
@Entity
@Table(name = "carts")
public class Cart {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    /*
     * cascade = ALL + orphanRemoval = true ← КОРЗИНА полностью владеет ITEMS.
     * Если удалить CartItem из списка → он удалится из БД автоматически.
     * Если удалить Cart → все его Items удалятся каскадом.
     */
    @OneToMany(mappedBy = "cart", 
              cascade = CascadeType.ALL, 
              orphanRemoval = true)
    private List<CartItem> items = new ArrayList<>();
}
CartItem.java
@Entity
@Table(name = "cart_items")
public class CartItem {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private Integer quantity = 1;

    // Связь с корзиной (владелец)
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "cart_id", nullable = false)
    private Cart cart;

    // Связь с товаром (владелец)
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "product_id", nullable = false)
    private Product product;
}
3. Order (1) ↔ (N) OrderItem
Order.java
@Entity
@Table(name = "orders")
public class Order {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private LocalDateTime createdAt = LocalDateTime.now();

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private OrderStatus status = OrderStatus.PENDING;

    // Заказ владеет своими позициями.Cascade ALL уместен, т.к. OrderItem не существует без Order
    @OneToMany(mappedBy = "order", cascade = CascadeType.ALL, orphanRemoval = true)
    private List<OrderItem> items = new ArrayList<>();
}
OrderItem.java
@Entity
@Table(name = "order_items")
public class OrderItem {
    @Id @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private Integer quantity;

    // ⚠️ ВАЖНО: Копируем цену и название на момент покупки!
    // Товар может подорожать позже, но история заказа должна остаться неизменной.
    @Column(nullable = false, precision = 10, scale = 2)
    private BigDecimal snapshotPrice;

    @Column(nullable = false, length = 255)
    private String snapshotProductName;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "order_id", nullable = false)
    private Order order;

    // product_id может быть nullable, если товар был удалён из каталога, но заказ остался
    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "product_id")
    private Product product;
}

💡 Про сущность Item
В реальных проектах CartItem и OrderItem часто наследуются от базового класса Item (через @MappedSuperclass), чтобы не дублировать поля quantity и snapshotPrice. Но для простоты и избежания проблем с полиморфными запросами в JPA, лучше держать их отдельными сущностями, как показано выше.

🔄 Синхронизация двусторонней связи

Если ты добавишь товар в категорию только со стороны Category, Hibernate не обновит FK в БД, потому что слушает только владельца (Product.category). Нужно обновлять обе стороны или использовать helper-методы.

Helper-методы в Product.java
// Добавляем в Product.java для безопасной работы
public void setCategory(Category category) {
    // 1. Отвязываем от старой категории
    if (this.category != null) {
        this.category.getProducts().remove(this);
    }
    // 2. Привязываем к новой
    this.category = category;
    if (category != null) {
        category.getProducts().add(this);
    }
}

// Использование в сервисе:
product.setCategory(electronicsCategory);  // Обновит и product.category, и category.products
productRepository.save(product);           // Hibernate сгенерирует UPDATE products SET category_id=?

✅ Best & ⚠️ Anti Practices

✅ Best Practices
  • Всегда ставь fetch = LAZY на @ManyToOne и @OneToMany
  • Используй cascade = ALL + orphanRemoval = true только для композиций (Cart→Items, Order→Items)
  • Никогда не каскадируй удаление на агрегаты (Category→Products, Product→OrderItems)
  • Добавляй helper-методы (setCategory(), addItem()) для синхронизации
  • Копируй цену/название в OrderItem (snapshot), а не ссылайся на Product
  • Возвращай DTO, а не Entity, чтобы избежать LazyInitializationException
  • Используй @EntityGraph или JOIN FETCH для решения N+1
⚠️ Anti Patterns
  • ❌ Оставлять EAGER на коллекциях (приведёт к OutOfMemory и N+1)
  • ❌ Забывать mappedBy (Hibernate создаст лишнюю таблицу/столбец)
  • ❌ Ставить cascade = REMOVE на @ManyToOne (удаление товара удалит категорию!)
  • ❌ Менять только inverse side (данные в БД не обновятся)
  • ❌ Хранить актуальную цену товара в OrderItem (история заказа "поплывёт")
  • ❌ Сериализовать Entity в JSON без DTO (бесконечная рекурсия Jackson)
  • ❌ Игнорировать nullable = false на FK, если связь обязательна

❓ Вопросы для собеседования

Почему @ManyToOne — это owning side, а @OneToMany — inverse?
Why is @ManyToOne owning and @OneToMany inverse?
Medium ▼
✅ Ответ
В реляционной БД внешний ключ (FK) физически хранится в таблице "многих" (например, products.category_id). JPA следует этой логике: сторона, которая хранит FK в БД, является владельцем связи. @OneToMany не хранит FK, а только читает данные через JOIN, поэтому она объявляется через mappedBy как зеркало. Hibernate генерирует SQL-операции только на основе состояния owning side.
В чём разница между cascade = ALL и orphanRemoval = true?
Difference between cascade ALL and orphanRemoval?
Hard ▼
✅ Ответ
cascade = ALL распространяет операции (persist, merge, remove) на связанные сущности при явном вызове на родителе. orphanRemoval = true отслеживает изменения в коллекции: если элемент удаляется из списка (cart.getItems().remove(item)), Hibernate автоматически выполнит DELETE для этого элемента, даже если родитель не удаляется. orphanRemoval подразумевает cascade = ALL и используется только для строгих композиций "жизнь-смерть" (Cart→Items).
Что такое N+1 проблема и как её избежать с @OneToMany?
What is N+1 problem and how to avoid it with @OneToMany?
Hard ▼
✅ Ответ
При загрузке списка категорий (1 запрос) и ленивой инициализации их товаров Hibernate выполняет N дополнительных запросов (по одному на категорию). Решения: 1) @EntityGraph(attributePaths = {"products"}) в Spring Data, 2) JPQL с JOIN FETCH c.products, 3) @BatchSize(size = 20) для групповой загрузки, 4) Возвращать DTO через конструкторный JPQL вместо Entity. Никогда не используй EAGER как "лечение" N+1.
