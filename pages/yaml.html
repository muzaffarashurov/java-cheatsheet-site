📌 Краткий конспект
YAML vs Properties
YAML (Yet Another Markup Language) — иерархический формат конфигурации. Предпочтительнее .properties для Spring Boot: иерархия видна визуально, поддерживает списки и вложенные объекты без повторения префикса.
PropertiesYAML эквивалент
spring.datasource.url=jdbc:...spring.datasource.url: jdbc:...
spring.datasource.username=userspring.datasource.username: user
server.port=8080server.port: 8080
💡 Приоритет источников конфигурации (от высшего к низшему)
1. Аргументы командной строки: --server.port=9090
2. ENV переменные: SERVER_PORT=9090
3. application-{profile}.yml (активный профиль)
4. application.yml
5. Дефолтные значения в коде: @Value("${prop:default}")

🌱 application.yml — полный шаблон
YAML — application.yml
# ════════════════════════════════════════════
   Spring Boot application.yml — полный шаблон
   ════════════════════════════════════════════

# ── Информация о приложении
spring:
  application:
    name: my-application                   # имя сервиса (видно в Actuator, логах)

  # ── База данных
  datasource:
    url: ${DATABASE_URL:jdbc:postgresql://localhost:5432/mydb}  # ENV или дефолт
    username: ${DATABASE_USERNAME:myuser}
    password: ${DATABASE_PASSWORD}         # без дефолта — обязателен
    driver-class-name: org.postgresql.Driver
    hikari:                                # HikariCP connection pool
      maximum-pool-size: 10                # максимум соединений
      minimum-idle: 2                      # минимум idle соединений
      connection-timeout: 30000            # таймаут получения соединения (мс)
      idle-timeout: 600000                 # время жизни idle соединения
      max-lifetime: 1800000                # максимальное время жизни соединения
      pool-name: MyAppPool                 # имя пула (видно в мониторинге)

  # ── JPA / Hibernate
  jpa:
    hibernate:
      ddl-auto: validate                   # validate/update/create/create-drop/none
    show-sql: false                        # true только для dev!
    properties:
      hibernate:
        format_sql: true                   # форматировать SQL в логах
        dialect: org.hibernate.dialect.PostgreSQLDialect
        default_batch_fetch_size: 20       # batch загрузка связей
        order_inserts: true                # группировать INSERT'ы
        order_updates: true

  # ── Redis
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
      password: ${REDIS_PASSWORD:}         # пустой = без пароля
      timeout: 2000ms
      lettuce:
        pool:
          max-active: 10
          max-idle: 5
          min-idle: 1

  # ── Kafka
  kafka:
    bootstrap-servers: ${KAFKA_SERVERS:localhost:9092}
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.springframework.kafka.support.serializer.JsonSerializer
      acks: all
    consumer:
      group-id: ${spring.application.name}-group
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.springframework.kafka.support.serializer.JsonDeserializer
      auto-offset-reset: earliest
      enable-auto-commit: false

  # ── Кэширование
  cache:
    type: redis
    redis:
      time-to-live: 3600000               # TTL 1 час в мс

  # ── Email
  mail:
    host: ${MAIL_HOST:smtp.gmail.com}
    port: ${MAIL_PORT:587}
    username: ${MAIL_USERNAME}
    password: ${MAIL_PASSWORD}
    properties:
      mail.smtp.auth: true
      mail.smtp.starttls.enable: true

  # ── Graceful shutdown
  lifecycle:
    timeout-per-shutdown-phase: 30s

# ── Сервер
server:
  port: ${SERVER_PORT:8080}
  shutdown: graceful                       # дождаться завершения запросов
  servlet:
    context-path: /                        # базовый путь
  compression:
    enabled: true                          # gzip сжатие ответов
    mime-types: application/json,text/html
    min-response-size: 1024                # сжимать если > 1KB
  error:
    include-message: never                 # не включать message в /error ответ
    include-stacktrace: never              # никогда не показывать стектрейс

# ── Actuator
management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics,prometheus  # доступные эндпоинты
      base-path: /actuator
  endpoint:
    health:
      show-details: when-authorized        # детали только авторизованным
      probes:
        enabled: true                      # /health/liveness, /health/readiness для K8s
  info:
    env:
      enabled: true                        # показывать info.* properties
  server:
    port: 8081                             # отдельный порт для Actuator в проде

# ── Логирование
logging:
  level:
    root: INFO                             # уровень по умолчанию
    com.company.myapp: DEBUG               # наш пакет — DEBUG
    org.springframework.web: WARN
    org.hibernate.SQL: DEBUG               # SQL запросы (только dev!)
    org.hibernate.type.descriptor.sql: TRACE  # параметры SQL
  pattern:
    console: "%d{HH:mm:ss} [%thread] %-5level %logger{36} - %msg%n"
  file:
    name: logs/application.log             # файл логов
    max-size: 100MB
    max-history: 30                        # хранить 30 дней

# ── Информация о приложении (Actuator /info)
info:
  app:
    name: ${spring.application.name}
    version: "@project.version@"           # из pom.xml через Maven filtering
    description: My Spring Boot Application

# ── Кастомные свойства приложения
app:
  jwt:
    secret: ${JWT_SECRET}                  # ОБЯЗАТЕЛЬНО из ENV!
    expiration: 86400000                   # 24 часа в мс
  mail:
    from: noreply@myapp.com
    template-path: /templates/email/
  pagination:
    default-page-size: 20
    max-page-size: 100
🎭 Profiles — разные конфигурации

Профили позволяют иметь разные конфигурации для разных окружений. Spring Boot автоматически загружает application-{profile}.yml поверх базового application.yml.

Способы активации
  • В application.yml: spring.profiles.active: dev
  • ENV переменная: SPRING_PROFILES_ACTIVE=prod
  • Аргумент JVM: -Dspring.profiles.active=prod
  • Аргумент командной строки: --spring.profiles.active=prod
Файловая структура
  • application.yml — базовая конфигурация
  • application-dev.yml — переопределяет для dev
  • application-prod.yml — переопределяет для prod
  • application-test.yml — для тестов

🔐 Секреты и ENV переменные
🚫 Никогда не коммить секреты в Git
Пароли БД, JWT ключи, API токены — никогда в application.yml или .properties в репозитории. Используй ENV переменные, .env файл (в .gitignore), Vault, или менеджер секретов облачного провайдера.

✅ Best Practices
✅ Правильно
  • ENV переменные для секретов: ${JWT_SECRET}
  • @ConfigurationProperties для группы свойств
  • Дефолтные значения для необязательных свойств
  • Профили для разных окружений
  • Валидация конфига: @Validated на @ConfigurationProperties
  • spring.jpa.show-sql=false в продакшене
  • server.error.include-stacktrace=never
  • Отдельный порт для Actuator
🚫 Ошибки
  • Пароли в application.yml в репозитории
  • ddl-auto: create-drop в продакшене
  • show-sql: true в продакшене — заливает логи
  • Открытый Actuator без защиты
  • Нет дефолтных значений для обязательных свойств
  • Смешивать конфигурацию всех окружений в одном файле

3. @ConfigurationProperties — type-safe конфигурация
Java + YAML
// ── application.yml
// app:
//   jwt:
//     secret: ${JWT_SECRET}
//     expiration: 86400000
//     refresh-expiration: 604800000
//   cors:
//     allowed-origins:
//       - https://frontend.example.com
//   pagination:
//     default-size: 20
//     max-size: 100

@ConfigurationProperties(prefix = "app")  // читаем всё начинающееся с "app."
@Component
@Validated                                  // валидация при старте!
public class AppProperties {

    private Jwt        jwt        = new Jwt();
    private Cors       cors       = new Cors();
    private Pagination pagination = new Pagination();

    // геттеры/сеттеры...

    public static class Jwt {
        @NotBlank                             // не может быть пустым
        private String secret;
        @Positive
        private long   expiration        = 86400000L;
        @Positive
        private long   refreshExpiration = 604800000L;
        // геттеры/сеттеры...
    }

    public static class Cors {
        @NotEmpty                             // список не пустой
        private List<String> allowedOrigins = new ArrayList<>();
        private List<String> allowedMethods = List.of("GET","POST","PUT","DELETE");
        // геттеры/сеттеры...
    }

    public static class Pagination {
        @Min(1) @Max(100)
        private int defaultSize = 20;
        @Min(1) @Max(1000)
        private int maxSize     = 100;
        // геттеры/сеттеры...
    }
}

// ── Использование в сервисе
@Service
@RequiredArgsConstructor
public class JwtService {
    private final AppProperties appProperties;

    public String generateToken(UserDetails user) {
        long exp = appProperties.getJwt().getExpiration(); // type-safe!
        // ...
    }
}

// ── @Value — одиночные свойства
@Service
public class SomeService {

    @Value("${app.mail.from}")
    private String mailFrom;                  // из application.yml

    @Value("${app.pagination.default-size:20}")
    private int defaultPageSize;              // дефолт = 20

    @Value("${JAVA_HOME}")
    private String javaHome;                  // ENV переменная

    @Value("#{T(java.lang.Math).PI}")
    private double pi;                        // SpEL выражение

    @Value("${app.cors.allowed-origins}")
    private List<String> allowedOrigins;     // Spring преобразует список
}
❓ Вопросы для собеседования
Чем @Value отличается от @ConfigurationProperties?
What is the difference between @Value and @ConfigurationProperties?
Medium▼
✅ Ответ
@Value("${prop}") инжектирует одно свойство — просто, но размазывает конфигурацию по коду, нет type-safety, нет IDE автодополнения. @ConfigurationProperties(prefix="app") маппит группу свойств на класс — type-safe, IDE автодополнение, можно добавить @Validated для проверки при старте. Рекомендуется для любой группы из 2+ связанных свойств.
Как работают Spring профили?
How do Spring profiles work?
Medium▼
✅ Ответ
Профили позволяют иметь разные конфигурации для разных окружений. Базовый application.yml загружается всегда. При активном профиле prod дополнительно загружается application-prod.yml — он переопределяет значения из базового. Активируется через spring.profiles.active, ENV переменную SPRING_PROFILES_ACTIVE, или аргумент командной строки.
Как не хранить секреты в application.yml?
How do you avoid storing secrets in application.yml?
Medium▼
✅ Ответ
Использовать плейсхолдеры: ${JWT_SECRET} — Spring подставит значение из ENV переменной. В application.yml хранится только ссылка на переменную, а само значение — в операционной системе, CI/CD системе (GitHub Secrets), Kubernetes Secret, или HashiCorp Vault. .env файл для локальной разработки добавляется в .gitignore.
Что такое spring.jpa.hibernate.ddl-auto и какое значение использовать в продакшене?
What is ddl-auto and what value should you use in production?
Medium▼
✅ Ответ
none — ничего не делать ✅ продакшен
validate — проверить схему соответствует Entity (не меняет) ✅ продакшен
update — добавить недостающие колонки ⚠️ только dev
create — пересоздать схему при старте ❌ нельзя в проде
create-drop — создать и удалить при остановке ❌ только тесты
В продакшене используй Flyway или Liquibase для управления миграциями.
