GlobalExceptionHandler

Spring Exceptions AOP REST

@ControllerAdvice, @ExceptionHandler, единый формат ошибок, обработка валидации, кастомные исключения — централизованная обработка всех ошибок REST API в одном месте.

📌 Краткий конспект
Зачем нужен GlobalExceptionHandler
Без него каждое необработанное исключение вернёт клиенту HTML страницу с ошибкой Tomcat или стектрейс — непригодно для REST API. GlobalExceptionHandler перехватывает все исключения из контроллеров, сервисов и фильтров, и возвращает единообразный JSON ответ с правильным HTTP статусом.

💡 Приоритет обработчиков
Spring выбирает наиболее специфичный обработчик. @ExceptionHandler(ResourceNotFoundException.class) имеет приоритет над @ExceptionHandler(RuntimeException.class) и над @ExceptionHandler(Exception.class). Обработчик Exception — последний резерв для всего остального.

📋 Стандартный формат ErrorResponse

Важно иметь единый формат ошибок во всём API. Клиент (frontend, мобильное приложение) должен знать структуру ошибки заранее и обрабатывать её одинаково.

Пример ErrorResponse JSON
JSON — одиночная ошибка
// Для ResourceNotFoundException, AccessDeniedException и др.
{
  "status":    404,
  "error":     "Not Found",
  "message":   "User с id 42 не найден",
  "path":      "/api/v1/users/42",
  "timestamp": "2025-01-15T10:30:00Z"
}
JSON — ошибки валидации (список)
// Для MethodArgumentNotValidException (несколько полей)
{
  "status":    400,
  "error":     "Validation Failed",
  "message":   "Ошибка валидации входных данных",
  "path":      "/api/v1/users",
  "timestamp": "2025-01-15T10:30:00Z",
  "errors": [
    { "field": "email",    "message": "must be a well-formed email address" },
    { "field": "password", "message": "size must be between 8 and 100" },
    { "field": "name",     "message": "must not be blank" }
  ]
}

✅ Best Practices
✅ Правильно
  • Единый формат ошибок во всём API
  • Никогда не возвращай стектрейс клиенту
  • Логируй 5xx ошибки через log.error()
  • 4xx ошибки логируй через log.warn()
  • Кидай бизнесовые исключения из сервиса
  • Обрабатывай ошибки валидации по каждому полю
  • Добавляй path и timestamp в ответ
  • Финальный Exception.class ловит всё остальное
🚫 Ошибки
  • Возвращать стектрейс клиенту — утечка информации
  • Разные форматы ошибок в разных эндпоинтах
  • Проглатывать исключения без логирования
  • Возвращать 200 OK при ошибке в теле
  • Обработчики в каждом контроллере отдельно
  • Не обрабатывать ошибки валидации — клиент не знает что не так
💻 Примеры кода
1. ErrorResponse DTO
Java
// ── Класс для ошибки одного поля (валидация)
public record FieldError(
    String field,    // имя поля: "email", "name"
    String message   // сообщение: "must not be blank"
) {}

// ── Основной класс ответа об ошибке
@Getter
@Builder
public class ErrorResponse {

    private final int         status;     // HTTP статус код: 400, 404, 500
    private final String      error;      // краткое название: "Not Found"
    private final String      message;    // подробное сообщение
    private final String      path;       // URL запроса
    private final Instant     timestamp;  // время ошибки

    @JsonInclude(JsonInclude.Include.NON_NULL)  // не включать если null
    private final List<FieldError> errors;     // ошибки полей (только для валидации)

    // ── Фабричный метод для одиночной ошибки
    public static ErrorResponse of(
            HttpStatus status,
            String message,
            HttpServletRequest request) {
        return ErrorResponse.builder()
            .status(status.value())
            .error(status.getReasonPhrase())     // "Not Found", "Bad Request" и т.д.
            .message(message)
            .path(request.getRequestURI())      // "/api/v1/users/42"
            .timestamp(Instant.now())
            .build();
    }

    // ── Фабричный метод для ошибок валидации
    public static ErrorResponse ofValidation(
            List<FieldError> fieldErrors,
            HttpServletRequest request) {
        return ErrorResponse.builder()
            .status(HttpStatus.BAD_REQUEST.value())
            .error("Validation Failed")
            .message("Ошибка валидации входных данных")
            .path(request.getRequestURI())
            .timestamp(Instant.now())
            .errors(fieldErrors)
            .build();
    }
}
2. Полный GlobalExceptionHandler
Java
@RestControllerAdvice                              // = @ControllerAdvice + @ResponseBody
@Slf4j                                             // Lombok логгер
public class GlobalExceptionHandler {

    // ══════════════════════════════════════════════
       Наши бизнесовые исключения
       ══════════════════════════════════════════════ */

    // ── 404 Not Found — ресурс не найден
    @ExceptionHandler(ResourceNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)              // устанавливаем статус
    public ErrorResponse handleNotFound(
            ResourceNotFoundException ex,
            HttpServletRequest request) {
        log.warn("Resource not found: {} — {}", request.getRequestURI(), ex.getMessage());
        return ErrorResponse.of(HttpStatus.NOT_FOUND, ex.getMessage(), request);
    }

    // ── 409 Conflict — конфликт (дубликат email и т.д.)
    @ExceptionHandler(EmailAlreadyExistsException.class)
    @ResponseStatus(HttpStatus.CONFLICT)
    public ErrorResponse handleConflict(
            EmailAlreadyExistsException ex,
            HttpServletRequest request) {
        log.warn("Conflict: {}", ex.getMessage());
        return ErrorResponse.of(HttpStatus.CONFLICT, ex.getMessage(), request);
    }

    // ── Универсальный обработчик для всех AppException
    // (включая InsufficientFundsException → 422 и др.)
    @ExceptionHandler(AppException.class)
    public ResponseEntity<ErrorResponse> handleAppException(
            AppException ex,
            HttpServletRequest request) {
        log.warn("App exception [{}]: {}", ex.getStatus(), ex.getMessage());
        ErrorResponse body = ErrorResponse.of(ex.getStatus(), ex.getMessage(), request);
        return ResponseEntity.status(ex.getStatus()).body(body); // статус из исключения
    }

    /* ══════════════════════════════════════════════
       Ошибки валидации Spring / Jakarta
       ══════════════════════════════════════════════ */

    // ── 400 — @Valid на @RequestBody провалился
    @ExceptionHandler(MethodArgumentNotValidException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResponse handleValidation(
            MethodArgumentNotValidException ex,
            HttpServletRequest request) {

        // Собираем все ошибки полей в список
        List<FieldError> fieldErrors = ex.getBindingResult()
            .getFieldErrors()                           // все ошибки полей
            .stream()
            .map(fe -> new FieldError(
                fe.getField(),                          // "email", "name" и т.д.
                fe.getDefaultMessage()))                 // сообщение аннотации
            .toList();

        log.warn("Validation failed: {} errors", fieldErrors.size());
        return ErrorResponse.ofValidation(fieldErrors, request);
    }

    // ── 400 — @Validated на параметрах метода
    @ExceptionHandler(ConstraintViolationException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResponse handleConstraintViolation(
            ConstraintViolationException ex,
            HttpServletRequest request) {

        List<FieldError> fieldErrors = ex.getConstraintViolations()
            .stream()
            .map(cv -> new FieldError(
                cv.getPropertyPath().toString(),        // путь к полю
                cv.getMessage()))                         // сообщение
            .toList();

        return ErrorResponse.ofValidation(fieldErrors, request);
    }

    // ── 400 — невалидный JSON в теле запроса
    @ExceptionHandler(HttpMessageNotReadableException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResponse handleNotReadable(
            HttpMessageNotReadableException ex,
            HttpServletRequest request) {
        log.warn("Malformed JSON: {}", ex.getMessage());
        return ErrorResponse.of(HttpStatus.BAD_REQUEST,
            "Невалидный формат JSON в теле запроса", request);
    }

    // ── 400 — отсутствует обязательный @RequestParam
    @ExceptionHandler(MissingServletRequestParameterException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResponse handleMissingParam(
            MissingServletRequestParameterException ex,
            HttpServletRequest request) {
        String msg = "Отсутствует параметр '" + ex.getParameterName() + "'";
        return ErrorResponse.of(HttpStatus.BAD_REQUEST, msg, request);
    }

    // ── 400 — неверный тип параметра (строка вместо Long)
    @ExceptionHandler(MethodArgumentTypeMismatchException.class)
    @ResponseStatus(HttpStatus.BAD_REQUEST)
    public ErrorResponse handleTypeMismatch(
            MethodArgumentTypeMismatchException ex,
            HttpServletRequest request) {
        String msg = String.format(
            "Параметр '%s' должен быть типа %s",
            ex.getName(),
            ex.getRequiredType() != null
                ? ex.getRequiredType().getSimpleName()
                : "unknown");
        return ErrorResponse.of(HttpStatus.BAD_REQUEST, msg, request);
    }

    /* ══════════════════════════════════════════════
       Spring Security исключения
       ══════════════════════════════════════════════ */

    // ── 403 Forbidden — нет прав
    @ExceptionHandler(AccessDeniedException.class)
    @ResponseStatus(HttpStatus.FORBIDDEN)
    public ErrorResponse handleAccessDenied(
            AccessDeniedException ex,
            HttpServletRequest request) {
        log.warn("Access denied to {}: {}", request.getRequestURI(), ex.getMessage());
        return ErrorResponse.of(HttpStatus.FORBIDDEN,
            "Доступ запрещён", request);                // не раскрываем детали
    }

    /* ══════════════════════════════════════════════
       405, 415, финальный резерв
       ══════════════════════════════════════════════ */

    // ── 405 Method Not Allowed
    @ExceptionHandler(HttpRequestMethodNotSupportedException.class)
    @ResponseStatus(HttpStatus.METHOD_NOT_ALLOWED)
    public ErrorResponse handleMethodNotAllowed(
            HttpRequestMethodNotSupportedException ex,
            HttpServletRequest request) {
        String msg = "Метод " + ex.getMethod() + " не поддерживается";
        return ErrorResponse.of(HttpStatus.METHOD_NOT_ALLOWED, msg, request);
    }

    // ── 500 — финальный резерв для всего остального
    @ExceptionHandler(Exception.class)
    @ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
    public ErrorResponse handleAll(
            Exception ex,
            HttpServletRequest request) {
        log.error("Unhandled exception at {}: {}",          // 500 логируем как error!
            request.getRequestURI(), ex.getMessage(), ex); // третий аргумент = стектрейс в лог
        return ErrorResponse.of(HttpStatus.INTERNAL_SERVER_ERROR,
            "Внутренняя ошибка сервера", request);         // клиенту — без деталей!
    }
}
3. Кастомные исключения с HTTP статусом
Java
// ── Базовый класс всех исключений приложения
public abstract class AppException extends RuntimeException {
    private final HttpStatus status;

    protected AppException(String message, HttpStatus status) {
        super(message);
        this.status = status;
    }
    public HttpStatus getStatus() { return status; }
}

// ── 404
public class ResourceNotFoundException extends AppException {
    public ResourceNotFoundException(String resource, Long id) {
        super(resource + " с id " + id + " не найден", HttpStatus.NOT_FOUND);
    }
    public ResourceNotFoundException(String resource, String field, String value) {
        super(resource + " [" + field + "=" + value + "] не найден", HttpStatus.NOT_FOUND);
    }
}

// ── 409
public class EmailAlreadyExistsException extends AppException {
    public EmailAlreadyExistsException(String email) {
        super("Email '" + email + "' уже зарегистрирован", HttpStatus.CONFLICT);
    }
}

// ── 422
public class InsufficientFundsException extends AppException {
    public InsufficientFundsException(Long accountId, BigDecimal amount) {
        super("Недостаточно средств на счёте " + accountId +
              ". Требуется: " + amount, HttpStatus.UNPROCESSABLE_ENTITY);
    }
}

// ── Использование в сервисе:
throw new ResourceNotFoundException("User", id);        // → 404
throw new EmailAlreadyExistsException(email);             // → 409
throw new InsufficientFundsException(accountId, amount); // → 422
4. Тест GlobalExceptionHandler через MockMvc
Java
@WebMvcTest(UserController.class)              // только Web слой, без БД
class GlobalExceptionHandlerTest {

    @Autowired
    private MockMvc mockMvc;

    @MockBean                                       // мокируем сервис
    private UserService userService;

    @Test
    void getUser_notFound_returns404() throws Exception {
        // Сервис кидает исключение
        Mockito.when(userService.findById(999L))
            .thenThrow(new ResourceNotFoundException("User", 999L));

        // Выполняем запрос и проверяем ответ
        mockMvc.perform(get("/api/v1/users/999"))
            .andExpect(status().isNotFound())                // 404
            .andExpect(jsonPath("$.status").value(404))
            .andExpect(jsonPath("$.message").value(Matchers.containsString("999")))
            .andExpect(jsonPath("$.path").value("/api/v1/users/999"));
    }

    @Test
    void createUser_invalidBody_returns400WithFieldErrors() throws Exception {
        String invalidJson = """
            { "name": "", "email": "not-an-email", "password": "123" }
            """;                                              // невалидные данные

        mockMvc.perform(post("/api/v1/users")
                .contentType(MediaType.APPLICATION_JSON)
                .content(invalidJson))
            .andExpect(status().isBadRequest())              // 400
            .andExpect(jsonPath("$.status").value(400))
            .andExpect(jsonPath("$.errors").isArray())       // есть массив ошибок
            .andExpect(jsonPath("$.errors.length()").value(
                Matchers.greaterThan(0)));                  // хотя бы одна ошибка
    }
}
❓ Вопросы для собеседования
Что такое @ControllerAdvice и зачем он нужен?
What is @ControllerAdvice and why is it used?
Easy▼
✅ Ответ
@ControllerAdvice — класс который перехватывает исключения из всех контроллеров в одном месте. Без него каждое необработанное исключение вернёт клиенту стектрейс или Whitelabel Error Page. С ним — единый JSON формат ошибки с правильным HTTP статусом. @RestControllerAdvice = @ControllerAdvice + @ResponseBody, рекомендован для REST API.
Как обработать ошибки валидации @Valid и вернуть список полей?
How do you handle @Valid validation errors and return field-level errors?
Medium▼
✅ Ответ
При провале @Valid Spring кидает MethodArgumentNotValidException. В @ExceptionHandler получаем ошибки через ex.getBindingResult().getFieldErrors(). Каждый FieldError содержит имя поля и сообщение. Собираем в список и возвращаем в теле ответа — клиент знает точно какое поле невалидно.
Почему нельзя возвращать стектрейс клиенту?
Why should you never return a stack trace to the client?
Easy▼
✅ Ответ
Стектрейс раскрывает внутреннюю структуру приложения: имена классов, методов, версии библиотек, структуру БД. Это утечка информации — злоумышленник может использовать её для атаки (SQL injection, path traversal, exploit известных уязвимостей конкретной версии библиотеки). Стектрейс пишем в лог (log.error), клиенту возвращаем только "Внутренняя ошибка сервера".
Чем @ExceptionHandler в контроллере отличается от @ControllerAdvice?
What is the difference between @ExceptionHandler in a controller vs @ControllerAdvice?
Medium▼
✅ Ответ
@ExceptionHandler внутри контроллера — обрабатывает исключения только этого контроллера. Нужно дублировать в каждом контроллере. @ControllerAdvice — глобальный обработчик для всех контроллеров. Единое место, единый формат ошибок. Приоритет: обработчик в контроллере имеет приоритет над @ControllerAdvice для того же типа исключения.
Как Spring выбирает нужный @ExceptionHandler при нескольких?
How does Spring choose which @ExceptionHandler to use?
Medium▼
✅ Ответ
Spring выбирает наиболее специфичный тип исключения. Порядок: точное совпадение типа → ближайший родительский класс → Exception.class (самый общий). Если есть @ExceptionHandler(ResourceNotFoundException.class) и @ExceptionHandler(RuntimeException.class) — при ResourceNotFoundException выберет первый. Обработчик в контроллере имеет приоритет над @ControllerAdvice.
