📌 Краткий конспект
Ключевые факты

⚠️ Ловушка Integer кэша
Integer кэширует значения от -128 до 127. Для значений вне этого диапазона == вернёт false — всегда используй .equals()!
📝 Строки и String Pool

String в Java — immutable (неизменяемый). Любая операция создаёт новый объект. JVM хранит строковые литералы в специальной области — String Pool (часть Heap с Java 8+).

✅ String Pool (литерал)
  • Создаётся через "текст"
  • JVM проверяет пул → переиспользует
  • "a" == "a" → true
  • Экономит память
❌ new String()
  • Создаётся через new String("текст")
  • Всегда новый объект в Heap
  • new String("a") == new String("a") → false
  • Избегай без нужды

StringBuffer✅ Mutable✅ ДаМногопоточная конкатенация (редко нужен)
🧠 Память JVM: Stack и Heap
Stack (Стек)
  • Фреймы вызова методов
  • Локальные переменные и примитивы
  • Ссылки на объекты из Heap
  • Автоматически очищается при выходе из метода
  • Быстрый доступ (LIFO)
  • StackOverflowError → бесконечная рекурсия
Heap (Куча)
  • Все объекты (new …)
  • String Pool (Java 8+)
  • Статические поля классов
  • Управляется Garbage Collector
  • Медленнее Stack, но больше
  • OutOfMemoryError → утечка памяти
💡 Pass by value
Java — всегда передаёт по значению. Для примитивов передаётся копия значения. Для объектов — копия ссылки (не самого объекта). Поэтому изменение полей объекта внутри метода видно снаружи, но присвоение новой ссылки — нет.
🚨 Исключения (Exceptions)

Иерархия: Throwable → Error + Exception. Exception делится на Checked и Unchecked (RuntimeException).

ТипОписаниеПримерыОбязательно ловить?
ErrorКритические сбои JVMOutOfMemoryError, StackOverflowError❌ Не ловят
Checked ExceptionОжидаемые внешние сбоиIOException, SQLException✅ Да, компилятор требует
Unchecked ExceptionОшибки программистаNPE, IllegalArgumentException, ArrayIndexOutOfBoundsException❌ По желанию
Try-with-resources (Java 7+)
Ресурсы, реализующие AutoCloseable (потоки, соединения, readers), автоматически закрываются — даже при исключении. Это лучше, чем finally { close(); }.
⚖️ equals() и hashCode()

Контракт: если a.equals(b) == true, то a.hashCode() == b.hashCode() обязательно. Обратное — не обязательно. Нарушение контракта → объекты «теряются» в HashMap и HashSet.

⚠️ Когда ОБЯЗАТЕЛЬНО переопределять
Если кладёшь объект в HashMap, HashSet, LinkedHashMap — обязательно переопределяй оба метода. По умолчанию они сравнивают ссылки, а не содержимое.
🎁 Optional<T>

Optional — контейнер, который может содержать значение или быть пустым. Альтернатива null, которая делает возможность отсутствия значения явной.

✅ Best Practices / Bad Practices
✅ Best Practices
  • Используй try-with-resources для ресурсов
  • Всегда переопределяй equals + hashCode вместе
  • Используй Objects.equals() и Objects.hash()
  • Предпочитай Optional вместо возврата null
  • Используй List.of(), Map.of() для immutable коллекций
  • Предпочитай record (Java 16+) для DTO
  • Используй StringBuilder для конкатенации в цикле
  • Объявляй переменные максимально локально
🚫 Bad Practices
  • Сравнивать строки через ==
  • catch (Exception e) {} — проглатывать исключения
  • Возвращать null из метода без документации
  • Переопределять equals без hashCode
  • Конкатенация в цикле через +
  • Использовать float/double для денег (используй BigDecimal)
  • Ловить Error или Throwable
  • Хранить мутабельные объекты в static полях
⚠️ Частые ошибки и советы
NullPointerException — самая частая ошибка ▼

NPE возникает при попытке вызвать метод или обратиться к полю у null ссылки. С Java 14+ сообщение NPE стало информативным и показывает, что именно было null.

Профилактика: используй Optional, проверки Objects.requireNonNull(), аннотации @NonNull.

Memory Leak — утечка памяти ▼

GC не может собрать объект, если на него есть хотя бы одна живая ссылка. Частые причины: незакрытые потоки/соединения, статические коллекции, которые растут без ограничений, listeners без отписки.

Решение: try-with-resources, WeakReference для кэшей, профилировщик (VisualVM, YourKit).

Integer кэш — сюрприз со == ▼

JVM кэширует Integer от -128 до 127. Значит Integer.valueOf(100) == Integer.valueOf(100) → true, но Integer.valueOf(200) == Integer.valueOf(200) → false. Всегда используй .equals() для объектов.

💻 Примеры кода
1. Примитивы, Autoboxing и Integer кэш
Java 
// ── Примитивы хранятся в Stack, доступ быстрее
int age = 25;                          // примитив int, 4 байта в Stack
double salary = 75_000.50;             // _ для читаемости (Java 7+)
long population = 8_000_000_000L;     // суффикс L обязателен для long
boolean active = true;               // только true/false, не 0/1

// ── Autoboxing: компилятор автоматически упаковывает int → Integer
Integer boxed = 42;                   // == Integer.valueOf(42), не new Integer(42)
int unboxed = boxed;                   // Unboxing: Integer → int автоматически
// Внимание: unboxing из null вызовет NullPointerException!

// ── Integer кэш: значения -128..127 берутся из кэша JVM
Integer a = 127;                       // берётся из кэша Integer
Integer b = 127;                       // тот же объект из кэша
System.out.println(a == b);           // true — один и тот же объект

Integer x = 200;                       // вне кэша, новый объект в Heap
Integer y = 200;                       // ещё один новый объект
System.out.println(x == y);           // false — разные объекты!
System.out.println(x.equals(y));     // true — сравниваем содержимое, ПРАВИЛЬНО

// ── Полезные методы Integer
int parsed = Integer.parseInt("123");  // String → int, кидает NumberFormatException
String str = Integer.toString(456);   // int → String
int max = Integer.MAX_VALUE;           // 2 147 483 647
int min = Integer.MIN_VALUE;           // -2 147 483 648
String bin = Integer.toBinaryString(10); // "1010"
String hex = Integer.toHexString(255);  // "ff"
2. String Pool, сравнение и методы строк
Java 
// ── String Pool: литералы переиспользуются
String s1 = "Java";                    // создаётся в String Pool
String s2 = "Java";                    // берётся из Pool — тот же объект
String s3 = new String("Java");       // принудительно новый объект в Heap

System.out.println(s1 == s2);         // true — одна ссылка (пул)
System.out.println(s1 == s3);         // false — разные ссылки!
System.out.println(s1.equals(s3));   // true — содержимое одинаково ✅
System.out.println(s3.intern() == s1); // true — intern() помещает в пул

// ── Основные методы String
String name = "  Hello, World!  ";
System.out.println(name.trim());       // "Hello, World!" — убирает пробелы
System.out.println(name.strip());      // Java 11+, лучше trim для Unicode
System.out.println(name.length());     // 18 — количество символов
System.out.println(name.toUpperCase()); // "  HELLO, WORLD!  "
System.out.println(name.contains("World"));  // true
System.out.println(name.replace("World", "Java")); // "  Hello, Java!  "
System.out.println(name.indexOf("o"));  // 4 — индекс первого 'o'
System.out.println(name.substring(2, 7)); // "Hello"
boolean empty = "".isEmpty();          // true
boolean blank = "  ".isBlank();       // true (Java 11+)

// ── StringBuilder — быстрая конкатенация (не создаёт объект на каждый +)
StringBuilder sb = new StringBuilder(); // изменяемый буфер строки
for (int i = 0; i < 5; i++) {
    sb.append(i).append(",");           // append возвращает this — цепочка
}
sb.deleteCharAt(sb.length() - 1);    // удаляем последнюю запятую
String result = sb.toString();         // "0,1,2,3,4"

// ── Text Block (Java 15+) — многострочные строки без \n и \"
String json = """
    {
        "name": "Ivan",
        "age": 25
    }
    """;  // отступы убираются автоматически относительно """
3. Исключения и try-with-resources
Java 
// ── Стандартный try-catch-finally
try {
    int result = 10 / 0;               // кидает ArithmeticException
} catch (ArithmeticException e) {
    System.out.println("Деление на 0: " + e.getMessage()); // "/" by zero
} finally {
    System.out.println("finally всегда выполняется"); // даже при исключении
}

// ── Multi-catch (Java 7+) — несколько типов в одном catch
try {
    doSomething();
} catch (IOException | SQLException e) { // оба типа обрабатываются одинаково
    log.error("Ошибка: {}", e.getMessage());
}

// ── try-with-resources (Java 7+) — ресурс закрывается АВТОМАТИЧЕСКИ
try (BufferedReader reader = new BufferedReader(  // открываем ресурс в ()
        new FileReader("data.txt"))) {           // reader реализует AutoCloseable
    String line;
    while ((line = reader.readLine()) != null) {   // читаем до конца файла
        process(line);                              // обрабатываем строку
    }
} catch (IOException e) {
    System.err.println("Ошибка файла: " + e.getMessage());
}
// reader.close() вызывается автоматически — даже при исключении!

// ── Собственное исключение
public class UserNotFoundException extends RuntimeException { // Unchecked
    public UserNotFoundException(Long id) {
        super("Пользователь с id " + id + " не найден"); // сообщение в родитель
    }
}
// Использование:
throw new UserNotFoundException(42L); // кидаем наше исключение
4. equals(), hashCode() и Objects
Java 
import java.util.Objects;

public class User {
    private Long id;
    private String email;

    @Override
    public boolean equals(Object o) {        // параметр всегда Object
        if (this == o) return true;           // быстрая проверка — один объект
        if (!(o instanceof User user)) return false; // Java 16+: pattern matching
        return Objects.equals(id, user.id)          // null-safe сравнение
            && Objects.equals(email, user.email);   // по всем значимым полям
    }

    @Override
    public int hashCode() {
        return Objects.hash(id, email);   // тот же набор полей, что в equals!
    }                                       // Objects.hash обрабатывает null

    @Override
    public String toString() {
        return "User{id=" + id + ", email='" + email + "'}"; // для отладки
    }
}

// ── record (Java 16+) — equals/hashCode/toString АВТОМАТИЧЕСКИ!
public record UserRecord(Long id, String email) {}  // всё готово из коробки

// ── Использование
User u1 = new User(1L, "ivan@mail.ru");
User u2 = new User(1L, "ivan@mail.ru");
System.out.println(u1.equals(u2));  // true — содержимое одинаково
System.out.println(u1 == u2);       // false — разные объекты в Heap

var set = new HashSet<User>();       // HashSet использует hashCode + equals
set.add(u1);
System.out.println(set.contains(u2)); // true только если оба метода правильные
5. Optional — работа с отсутствием значения
Java 
// ── Создание Optional
Optional<String> present = Optional.of("Иван");         // есть значение
Optional<String> empty   = Optional.empty();            // пусто
Optional<String> maybe  = Optional.ofNullable(getUser()); // может быть null

// ── Получение значения
String name = present.get();                    // "Иван" (кидает если пусто!)
String def  = empty.orElse("Аноним");          // "Аноним" — значение по умолчанию
String lazy = empty.orElseGet(() -> loadDefault()); // ленивое вычисление
String safe = maybe.orElseThrow(               // кидает наше исключение
    () -> new UserNotFoundException(1L));

// ── Преобразование (map, filter)
Optional<Integer> len = present.map(String::length); // Optional[4]
Optional<String> upper = present
    .filter(s -> s.length() > 3)               // проходит если длина > 3
    .map(String::toUpperCase);               // "ИВАН"

// ── Пример из репозитория Spring
public User getById(Long id) {
    return userRepository.findById(id)        // возвращает Optional
        .orElseThrow(() -> new UserNotFoundException(id)); // или кидаем 404
}

// ── Что НЕ надо делать с Optional
// if (opt.isPresent()) { opt.get(); } — лучше orElse/map
// Optional в полях класса — не используй для полей, только как возврат метода
// Optional в параметрах — не принято, лучше перегрузка метода
❓ Вопросы для собеседования
В чём разница между == и .equals() в Java?
What is the difference between == and .equals() in Java?
Easy ▼
✅ Ответ (RU)
== сравнивает ссылки (адреса в памяти) — одинаковый ли объект. .equals() сравнивает содержимое по логике, определённой в классе. Для примитивов == сравнивает значения. Для строк всегда используй .equals().
✅ Answer (EN)
== compares references (memory addresses). .equals() compares content using the logic defined in the class. For primitives, == compares values. Always use .equals() for Strings and objects.
🔥 Сильный ответ
«== — сравнение идентичности (один ли объект в памяти), .equals() — сравнение эквивалентности (одинаковое ли содержимое). Для String важно помнить про String Pool: два литерала "abc" будут ==, но new String("abc") — нет. Поэтому для строк всегда .equals() или Objects.equals().»
⚠️ Типичная ошибка кандидата
Говорят только про строки, забывая про примитивы и про Integer кэш (-128..127).
Что такое String Pool и зачем он нужен?
What is the String Pool and why does it exist?
Medium ▼
✅ Ответ
String Pool — специальная область в Heap (с Java 8+), где JVM хранит интернированные строковые литералы. Когда ты пишешь "Java", JVM проверяет: есть ли такая строка в пуле? Если есть — возвращает ту же ссылку, не создавая новый объект. Это возможно потому что String в Java immutable (неизменяемый). Экономит память и ускоряет сравнение по ссылке.
🔥 Сильный ответ
«String Pool — это оптимизация JVM, основанная на том что String immutable. Раз строку нельзя изменить, её безопасно переиспользовать. С Java 8 пул переехал из PermGen в основной Heap. String.intern() позволяет добавить строку в пул принудительно. new String("abc") всегда создаёт новый объект в Heap, минуя пул.»
Чем Stack отличается от Heap в JVM?
What is the difference between Stack and Heap in JVM?
Medium ▼
✅ Ответ
Stack: хранит фреймы вызовов методов, локальные переменные, примитивы и ссылки. Управляется автоматически (LIFO). Каждый поток имеет свой Stack. StackOverflowError — бесконечная рекурсия.
Heap: все объекты, массивы, String Pool. Управляется GC. Общий для всех потоков. OutOfMemoryError — утечка памяти.
🔥 Добавить в ответ
«Локальная переменная int x = 5 живёт в Stack. new User() создаёт объект в Heap, а ссылка на него — в Stack. Когда метод завершается, его Stack-фрейм уничтожается. Объект в Heap живёт пока на него есть хотя бы одна живая ссылка.»
Контракт equals и hashCode — что это?
Explain the equals() and hashCode() contract.
Hard ▼
✅ Ответ
Контракт: если a.equals(b) → true, то a.hashCode() == b.hashCode() обязан быть true. Обратное необязательно (коллизии допустимы). Нарушение: если переопределить только equals без hashCode, объекты могут «потеряться» в HashMap/HashSet — два равных объекта попадут в разные bucket'ы и contains() вернёт false.
🔥 Сильный ответ
«HashMap сначала использует hashCode() для определения bucket'а, потом equals() для поиска внутри bucket'а. Если hashCode разный — equals не вызывается вообще, объект не найдётся. Поэтому оба метода должны использовать одни и те же поля. Lombok @EqualsAndHashCode или record решают это автоматически.»
Java передаёт аргументы по значению или по ссылке?
Does Java pass arguments by value or by reference?
Medium ▼
✅ Ответ
Java всегда передаёт по значению. Для примитивов — копия значения. Для объектов — копия ссылки. Это значит: изменение полей объекта внутри метода видно снаружи (работаем с тем же объектом через ссылку), но переприсвоение переменной (obj = new Obj()) снаружи не видно.
⚠️ Ошибка кандидата
Говорят «объекты передаются по ссылке» — это неточно. Передаётся копия ссылки. Нельзя изменить переменную снаружи через параметр метода.
Чем Checked исключения отличаются от Unchecked?
What is the difference between Checked and Unchecked exceptions?
Easy ▼
✅ Ответ
Checked: наследуют Exception (не RuntimeException). Компилятор требует их поймать или объявить в сигнатуре (throws). Пример: IOException, SQLException. Используются для ожидаемых внешних сбоев.
Unchecked: наследуют RuntimeException. Компилятор не требует обработки. Пример: NullPointerException, IllegalArgumentException. Обычно означают ошибку программиста.
💡 Совет
В Spring принято использовать Unchecked исключения (RuntimeException) — это позволяет GlobalExceptionHandler перехватывать их без объявления throws в каждом методе.
