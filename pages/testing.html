🔗 Интеграционные тесты
@DataJpaTest
  • Только JPA слой (Repository)
  • In-memory H2 база данных
  • Транзакция откатывается после каждого теста
  • Быстрые — не запускают весь контекст
  • Реальные SQL запросы к H2
Testcontainers
  • Реальная БД в Docker контейнере
  • PostgreSQL вместо H2
  • Тестирует специфичный SQL диалект
  • Медленнее — нужен Docker
  • Максимальная точность тестирования
💡 Когда использовать Testcontainers
Когда приложение использует PostgreSQL-специфичные функции (jsonb, array, CTE, Window Functions) — H2 их не поддерживает. Testcontainers запускает реальный PostgreSQL контейнер и гарантирует идентичное поведение с продакшеном.
✅ Best Practices
✅ Правильно
  • Название теста: methodName_condition_expectedResult
  • Один тест — одна проверка (один assert concept)
  • AAA: Arrange → Act → Assert
  • Использовать @DisplayName для читаемых отчётов
  • Мокировать внешние зависимости (БД, HTTP)
  • @WebMvcTest для контроллеров (быстро)
  • Тестировать граничные случаи: null, пустые, max
  • AssertJ вместо JUnit assertions — читаемее
🚫 Ошибки
  • Тест зависит от порядка выполнения других тестов
  • Тест обращается к реальной БД/сети (без мока)
  • Один тест проверяет 10 разных вещей
  • Не тестировать исключения и граничные случаи
  • @SpringBootTest везде — очень медленно
  • Тест знает слишком много о реализации
  • Имя теста: test1(), testMethod2() — непонятно

1. Unit тест сервиса с Mockito
Java
@ExtendWith(MockitoExtension.class)              // подключаем Mockito к JUnit 5
class UserServiceTest {

    @Mock
    private UserRepository userRepository;          // создаём mock репозитория

    @Mock
    private UserMapper userMapper;                   // mock маппера

    @Mock
    private PasswordEncoder passwordEncoder;

    @InjectMocks
    private UserService userService;                 // тестируемый объект — все @Mock инжектируются

    // ── Тест успешного получения пользователя
    @Test
    @DisplayName("findById: успешно возвращает пользователя по существующему ID")
    void findById_existingId_returnsUserResponse() {
        // ── ARRANGE (подготовка)
        Long userId = 1L;
        User user = User.builder()
            .id(userId).name("Иван").email("ivan@mail.ru")
            .build();
        UserResponse expected = new UserResponse(userId, "Иван", "ivan@mail.ru", "USER", null);

        Mockito.when(userRepository.findById(userId))     // задаём поведение мока
               .thenReturn(Optional.of(user));
        Mockito.when(userMapper.toResponse(user))
               .thenReturn(expected);

        // ── ACT (действие)
        UserResponse result = userService.findById(userId);

        // ── ASSERT (проверка)
        assertThat(result).isNotNull();
        assertThat(result.id()).isEqualTo(userId);
        assertThat(result.name()).isEqualTo("Иван");
        assertThat(result.email()).isEqualTo("ivan@mail.ru");

        Mockito.verify(userRepository).findById(userId); // проверяем что метод вызывался
        Mockito.verify(userMapper).toResponse(user);
    }

    // ── Тест: пользователь не найден → исключение
    @Test
    @DisplayName("findById: кидает ResourceNotFoundException если ID не существует")
    void findById_nonExistingId_throwsNotFoundException() {
        // ARRANGE
        Long userId = 999L;
        Mockito.when(userRepository.findById(userId))
               .thenReturn(Optional.empty());           // пользователь не найден

        // ACT + ASSERT
        assertThatThrownBy(() -> userService.findById(userId))
            .isInstanceOf(ResourceNotFoundException.class)
            .hasMessageContaining("999");              // сообщение содержит ID

        Mockito.verify(userMapper, Mockito.never()).toResponse(Mockito.any()); // mapper не вызывался
    }

    // ── Тест создания пользователя с ArgumentCaptor
    @Test
    @DisplayName("create: сохраняет пользователя с хэшированным паролем")
    void create_validRequest_savesUserWithHashedPassword() {
        // ARRANGE
        CreateUserRequest request = new CreateUserRequest(
            "Иван", "ivan@mail.ru", "password123", 25);
        User userToSave = new User();
        User savedUser  = User.builder().id(1L).build();
        UserResponse response = new UserResponse(1L, "Иван", "ivan@mail.ru", "USER", null);

        Mockito.when(userRepository.existsByEmail("ivan@mail.ru")).thenReturn(false);
        Mockito.when(userMapper.toEntity(request)).thenReturn(userToSave);
        Mockito.when(passwordEncoder.encode("password123")).thenReturn("$2a$12$hashed");
        Mockito.when(userRepository.save(Mockito.any())).thenReturn(savedUser);
        Mockito.when(userMapper.toResponse(savedUser)).thenReturn(response);

        // ACT
        UserResponse result = userService.create(request);

        // ASSERT
        assertThat(result).isNotNull();
        assertThat(result.id()).isEqualTo(1L);

        // Захватываем аргумент save() для проверки
        ArgumentCaptor<User> captor = ArgumentCaptor.forClass(User.class);
        Mockito.verify(userRepository).save(captor.capture());
        User capturedUser = captor.getValue();
        assertThat(capturedUser.getPassword()).isEqualTo("$2a$12$hashed"); // пароль хэширован
        assertThat(capturedUser.getRole()).isEqualTo(Role.ROLE_USER);
    }

    // ── Параметризованный тест
    @ParameterizedTest
    @ValueSource(strings = {"", "   ", "a"})          // граничные случаи для имени
    @DisplayName("create: кидает исключение при невалидном имени")
    void create_invalidName_throwsException(String invalidName) {
        CreateUserRequest request = new CreateUserRequest(
            invalidName, "email@mail.ru", "password123", 25);

        assertThatThrownBy(() -> userService.create(request))
            .isInstanceOf(IllegalArgumentException.class);
    }
}
2. @WebMvcTest — тест контроллера с MockMvc
Java
@WebMvcTest(UserController.class)                // только Web слой, без БД и сервисов
class UserControllerTest {

    @Autowired
    private MockMvc mockMvc;                        // автоконфигурируется

    @Autowired
    private ObjectMapper objectMapper;             // для сериализации в JSON

    @MockBean
    private UserService userService;               // мокируем сервис в Spring контексте

    @Test
    @DisplayName("GET /api/v1/users/{id}: возвращает 200 и пользователя")
    void getUser_existingId_returns200WithUser() throws Exception {
        // ARRANGE
        UserResponse user = new UserResponse(1L, "Иван", "ivan@mail.ru", "USER", null);
        Mockito.when(userService.findById(1L)).thenReturn(user);

        // ACT + ASSERT
        mockMvc.perform(get("/api/v1/users/1")           // GET запрос
                .accept(MediaType.APPLICATION_JSON))
            .andExpect(status().isOk())                  // 200 OK
            .andExpect(content().contentType(MediaType.APPLICATION_JSON))
            .andExpect(jsonPath("$.id").value(1))
            .andExpect(jsonPath("$.name").value("Иван"))
            .andExpect(jsonPath("$.email").value("ivan@mail.ru"))
            .andDo(print());                             // напечатать в консоль для отладки
    }

    @Test
    @DisplayName("GET /api/v1/users/{id}: возвращает 404 если пользователь не найден")
    void getUser_nonExistingId_returns404() throws Exception {
        Mockito.when(userService.findById(999L))
            .thenThrow(new ResourceNotFoundException("User", 999L));

        mockMvc.perform(get("/api/v1/users/999"))
            .andExpect(status().isNotFound())             // 404
            .andExpect(jsonPath("$.status").value(404));  // ErrorResponse.status
    }

    @Test
    @DisplayName("POST /api/v1/users: возвращает 201 и созданного пользователя")
    void createUser_validRequest_returns201() throws Exception {
        // ARRANGE
        CreateUserRequest request = new CreateUserRequest(
            "Иван", "ivan@mail.ru", "password123", 25);
        UserResponse response = new UserResponse(1L, "Иван", "ivan@mail.ru", "USER", null);
        Mockito.when(userService.create(Mockito.any())).thenReturn(response);

        // ACT + ASSERT
        mockMvc.perform(post("/api/v1/users")
                .contentType(MediaType.APPLICATION_JSON)
                .content(objectMapper.writeValueAsString(request)))  // объект → JSON
            .andExpect(status().isCreated())                 // 201
            .andExpect(jsonPath("$.id").value(1));
    }

    @Test
    @DisplayName("POST /api/v1/users: возвращает 400 при невалидном теле запроса")
    void createUser_invalidRequest_returns400() throws Exception {
        String invalidJson = """
            {"name": "", "email": "not-email", "password": "123"}
            """;

        mockMvc.perform(post("/api/v1/users")
                .contentType(MediaType.APPLICATION_JSON)
                .content(invalidJson))
            .andExpect(status().isBadRequest())             // 400
            .andExpect(jsonPath("$.errors").isArray());   // есть список ошибок

        Mockito.verifyNoInteractions(userService);          // сервис не вызывался
    }
}
3. @DataJpaTest — тест репозитория
Java
@DataJpaTest                                       // только JPA слой + H2 in-memory
@AutoConfigureTestDatabase(replace = Replace.NONE)  // не заменять БД (для Testcontainers)
class UserRepositoryTest {

    @Autowired
    private UserRepository userRepository;
    
    @Autowired
    private TestEntityManager entityManager;         // для setup данных

    @Test
    @DisplayName("findByEmail: находит пользователя по email")
    void findByEmail_existingEmail_returnsUser() {
        // ARRANGE — создаём данные через EntityManager
        User user = User.builder()
            .name("Иван")
            .email("ivan@mail.ru")
            .password("hashed")
            .role(Role.ROLE_USER)
            .build();
        entityManager.persistAndFlush(user);          // сохранить и сбросить в БД

        // ACT
        Optional<User> result = userRepository.findByEmail("ivan@mail.ru");

        // ASSERT
        assertThat(result).isPresent();
        assertThat(result.get().getName()).isEqualTo("Иван");
        assertThat(result.get().getEmail()).isEqualTo("ivan@mail.ru");
    }

    @Test
    @DisplayName("existsByEmail: возвращает false для несуществующего email")
    void existsByEmail_nonExistingEmail_returnsFalse() {
        boolean result = userRepository.existsByEmail("nobody@mail.ru");
        assertThat(result).isFalse();
    }
}
4. Testcontainers — реальная PostgreSQL в тестах
Java
@SpringBootTest
@Testcontainers                                    // включаем Testcontainers
@ActiveProfiles("test")
class UserIntegrationTest {

    // ── Запустить PostgreSQL контейнер (общий для всех тестов класса)
    @Container
    static PostgreSQLContainer<?> postgres =
        new PostgreSQLContainer<>("postgres:16-alpine") // реальный PostgreSQL!
            .withDatabaseName("testdb")
            .withUsername("test")
            .withPassword("test");

    // ── Подключить Spring к контейнеру
    @DynamicPropertySource
    static void configureProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url",      postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
    }

    @Autowired
    private UserRepository userRepository;

    @Test
    @Transactional                                  // откатить после теста
    void fullFlow_createAndFindUser() {
        User user = User.builder()
            .name("Интеграционный Тест")
            .email("integration@test.com")
            .password("$2a$12$hash")
            .role(Role.ROLE_USER)
            .build();

        User saved = userRepository.save(user);       // реальный INSERT в PostgreSQL

        assertThat(saved.getId()).isNotNull();
        assertThat(userRepository.findByEmail("integration@test.com"))
            .isPresent();
    }
}
❓ Вопросы для собеседования
Чем @Mock отличается от @MockBean?
What is the difference between @Mock and @MockBean?
Medium▼
✅ Ответ
@Mock — Mockito аннотация. Создаёт mock объект без Spring контекста. Используется с @ExtendWith(MockitoExtension.class) в unit тестах. @MockBean — Spring Test аннотация. Создаёт mock и регистрирует его как бин в Spring контексте, заменяя реальный бин. Используется в @WebMvcTest, @SpringBootTest.
Когда использовать @WebMvcTest vs @SpringBootTest?
When to use @WebMvcTest vs @SpringBootTest?
Medium▼
✅ Ответ
@WebMvcTest — тестируем только Web слой (контроллер, валидация, маппинг URL), сервисы мокируем через @MockBean. Быстрый — не поднимает полный контекст.
@SpringBootTest — поднимает весь контекст приложения. Используй для интеграционных тестов когда нужна реальная связь всех слоёв. Медленнее. Для БД — Testcontainers или @DataJpaTest.
Что такое AAA паттерн в тестировании?
What is the AAA pattern in testing?
Easy▼
✅ Ответ
AAA — Arrange, Act, Assert. Arrange — подготовка: создание объектов, настройка моков. Act — действие: вызов тестируемого метода. Assert — проверка: assertThat результата соответствует ожидаемому. Разделение визуально (комментарии или пустые строки) делает тест читаемым и понятным.
Чем Mockito spy отличается от mock?
What is the difference between a Mockito spy and a mock?
Medium▼
✅ Ответ
@Mock — полный mock: все методы возвращают дефолт (null, 0, false). Реальный код не выполняется. @Spy — обёртка над реальным объектом: методы выполняются реально, если не переопределены через doReturn().when(spy).method(). Spy используют когда нужно тестировать частично — некоторые методы реальные, некоторые мокированные.
Зачем нужен Testcontainers и как он работает?
What is Testcontainers and how does it work?
Hard▼
✅ Ответ
Testcontainers — библиотека для запуска Docker контейнеров в тестах. Нужен когда H2 не подходит: PostgreSQL-специфичные запросы, jsonb, массивы, полнотекстовый поиск. Работает: @Container PostgreSQLContainer запускает контейнер перед тестами, @DynamicPropertySource передаёт URL/credentials в Spring контекст. Тест работает с реальной БД и гарантирует идентичность продакшену.
