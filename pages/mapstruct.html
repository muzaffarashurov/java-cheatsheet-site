MapStruct

Spring Java Mapping Code Gen

MapStruct — генератор маппинга Entity ↔ DTO на этапе компиляции. Быстрее ModelMapper, type-safe, без рефлексии. @Mapper, @Mapping, @MappingTarget, кастомные конвертеры, Spring интеграция.

📌 Краткий конспект
Как работает MapStruct
MapStruct — аннотационный процессор. На этапе компиляции читает твои интерфейсы с @Mapper и генерирует обычный Java код (геттеры/сеттеры). Никакой рефлексии в рантайме — работает как ручной маппинг, но без бойлерплейта.

⚙️ Подключение в pom.xml
XML — pom.xml
<!-- Свойства для версий -->
<properties>
    <mapstruct.version>1.5.5.Final</mapstruct.version>
    <lombok.version>1.18.30</lombok.version>   <!-- Lombok тоже нужен -->
</properties>

<dependencies>
    <!-- MapStruct API -->
    <dependency>
        <groupId>org.mapstruct</groupId>
        <artifactId>mapstruct</artifactId>
        <version>${mapstruct.version}</version>
    </dependency>
</dependencies>

<build>
  <plugins>
    <plugin>
      <groupId>org.apache.maven.plugins</groupId>
      <artifactId>maven-compiler-plugin</artifactId>
      <configuration>
        <annotationProcessorPaths>
          <!-- Lombok ОБЯЗАТЕЛЬНО ПЕРЕД MapStruct -->
          <path>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
            <version>${lombok.version}</version>
          </path>
          <!-- MapStruct процессор -->
          <path>
            <groupId>org.mapstruct</groupId>
            <artifactId>mapstruct-processor</artifactId>
            <version>${mapstruct.version}</version>
          </path>
          <!-- Интеграция Lombok + MapStruct -->
          <path>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok-mapstruct-binding</artifactId>
            <version>0.2.0</version>
          </path>
        </annotationProcessorPaths>
      </configuration>
    </plugin>
  </plugins>
</build>
⚠️ Важно: порядок процессоров
Lombok должен идти перед MapStruct в annotationProcessorPaths. Иначе MapStruct не увидит геттеры/сеттеры сгенерированные Lombok и маппинг не скомпилируется.
🗺 Базовый маппинг

MapStruct автоматически маппит поля с одинаковыми именами и совместимыми типами. Если имена или типы отличаются — используй @Mapping.

СценарийЧто делает MapStruct
Одинаковое имя, одинаковый тип✅ Маппит автоматически
Одинаковое имя, совместимый тип (int → long)✅ Маппит с конвертацией
Одинаковое имя, String → int✅ Маппит через Integer.parseInt()
Разные имена❌ Нужен @Mapping(source, target)
Вложенный объект → поле❌ Нужен @Mapping(source="obj.field")
Enum → String✅ Через .name()
null значения✅ Передаёт как null

✏️ @MappingTarget — обновление существующего объекта

@MappingTarget позволяет обновлять поля существующего объекта вместо создания нового. Идеально для PUT/PATCH операций — не нужно создавать новый Entity при обновлении.

✅ Применение в сервисе
При обновлении: загружаем Entity из БД → маппим Request DTO в Entity через @MappingTarget → сохраняем. JPA dirty checking сам сделает UPDATE только изменённых полей.
🔧 Кастомные методы и конвертеры

Когда стандартного маппинга недостаточно — добавляй default методы в интерфейс маппера или помечай их @Named для использования в @Mapping(qualifiedByName=...).

АннотацияНазначение
@Named("methodName")Именовать метод для qualifiedByName
@BeforeMappingВызвать метод перед маппингом
@AfterMappingВызвать метод после маппинга
@ConditionУсловие — маппить поле или нет
default методВстроить логику прямо в маппер
uses = {OtherMapper.class}Переиспользовать другой маппер
🌱 Spring интеграция

@Mapper(componentModel = "spring") — MapStruct сгенерирует класс с @Component, который можно инжектировать через @Autowired или конструктор.

Сгенерированный код (упрощённо)
// MapStruct генерирует это автоматически:
@Component                                     // Spring бин!
public class UserMapperImpl implements UserMapper {

    @Override
    public UserResponse toResponse(User user) {
        if (user == null) return null;
        UserResponse userResponse = new UserResponse();
        userResponse.setId(user.getId());         // обычные геттеры/сеттеры
        userResponse.setName(user.getName());
        userResponse.setEmail(user.getEmail());
        return userResponse;
    }
}
// Никакой рефлексии — чистый быстрый Java код
✅ Best Practices
✅ Правильно
  • componentModel = "spring" всегда
  • Lombok перед MapStruct в процессорах
  • Явно игнорировать чувствительные поля (password)
  • Использовать @MappingTarget для обновления
  • Кастомные методы через @Named
  • Один маппер на доменный объект
  • Инжектировать маппер в сервис через конструктор
🚫 Ошибки
  • Забыть добавить componentModel = "spring"
  • Lombok после MapStruct в процессорах
  • Не игнорировать поля которые не должны маппиться
  • Маппинг в контроллере вместо сервиса
  • Слишком сложная логика в маппере — выноси в сервис
💻 Примеры кода
1. Базовый UserMapper
Java
// ── Entity
@Entity
@Table(name = "users")
@Data @Builder @NoArgsConstructor @AllArgsConstructor
public class User {
    @Id @GeneratedValue
    private Long    id;
    private String  firstName;       // разные имена!
    private String  lastName;
    private String  email;
    private String  password;        // секрет — не должен идти в DTO
    @Enumerated(EnumType.STRING)
    private Role    role;
    private Instant createdAt;
}

// ── DTO ответа
@Data                                           // Lombok: геттеры, сеттеры, equals, hashCode
public class UserResponse {
    private Long    id;
    private String  fullName;        // объединяем firstName + lastName
    private String  email;
    private String  role;            // Enum → String
    private Instant createdAt;
}

// ── DTO запроса
public record CreateUserRequest(
    @NotBlank String firstName,
    @NotBlank String lastName,
    @Email    String email,
    @Size(min=8) String password
) {}

// ── Маппер
@Mapper(componentModel = "spring")             // генерировать @Component Spring бин
public interface UserMapper {

    // ── Entity → Response DTO
    @Mapping(target = "fullName",               // поле назначения
             expression = "java(user.getFirstName() + ' ' + user.getLastName())")
    @Mapping(target = "role",
             expression = "java(user.getRole().name())")  // Enum → String
    UserResponse toResponse(User user);

    // ── Request DTO → Entity
    @Mapping(target = "id",        ignore = true) // id генерирует БД
    @Mapping(target = "password", ignore = true) // пароль хэшируется в сервисе
    @Mapping(target = "role",     ignore = true) // роль задаётся в сервисе
    @Mapping(target = "createdAt", ignore = true) // задаётся автоматически
    User toEntity(CreateUserRequest request);

    // ── Маппинг списка (MapStruct генерирует автоматически)
    List<UserResponse> toResponseList(List<User> users); // stream().map(toResponse)
}
2. @MappingTarget — обновление существующего Entity
Java
@Mapper(componentModel = "spring")
public interface UserMapper {

    // ── Обновление полей существующего Entity из DTO
    @Mapping(target = "id",        ignore = true)  // id не трогаем
    @Mapping(target = "password", ignore = true)  // пароль меняется отдельно
    @Mapping(target = "createdAt", ignore = true) // дата создания не меняется
    @Mapping(target = "role",     ignore = true)   // роль не меняется через update
    void updateEntity(UpdateUserRequest request,    // источник — DTO
                       @MappingTarget User user);  // цель — существующий Entity
    // MapStruct генерирует: user.setFirstName(request.firstName()); и т.д.
}

// ── Использование в сервисе
@Service
@RequiredArgsConstructor
public class UserService {
    private final UserRepository userRepository;
    private final UserMapper     userMapper;

    @Transactional
    public UserResponse update(Long id, UpdateUserRequest request) {
        User user = userRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("User", id));

        userMapper.updateEntity(request, user);     // обновляем поля Entity
        // JPA dirty checking сохранит изменения при коммите
        // save() не обязателен, но можно вызвать явно
        return userMapper.toResponse(userRepository.save(user));
    }
}
3. @Named — кастомные методы конвертации
Java
@Mapper(componentModel = "spring")
public interface ProductMapper {

    // ── Использование кастомного метода через qualifiedByName
    @Mapping(target = "price",
             source = "price",
             qualifiedByName = "formatPrice")    // использовать наш метод
    @Mapping(target = "category",
             source = "category.name")           // вложенный объект → строка
    @Mapping(target = "imageUrl",
             qualifiedByName = "buildImageUrl")
    ProductResponse toResponse(Product product);

    // ── Кастомный метод с @Named — форматируем цену
    @Named("formatPrice")                       // имя для qualifiedByName
    default String formatPrice(BigDecimal price) {
        if (price == null) return "0.00 ₽";
        return price.setScale(2, RoundingMode.HALF_UP) + " ₽"; // "99.99 ₽"
    }

    // ── Кастомный метод — строим URL изображения
    @Named("buildImageUrl")
    default String buildImageUrl(Product product) {
        if (product.getImagePath() == null) return null;
        return "/api/images/" + product.getId() + "/" + product.getImagePath();
    }

    // ── @BeforeMapping — действие перед маппингом
    @BeforeMapping
    default void beforeMapping(Product product, @MappingTarget ProductResponse response) {
        // Например: нормализация данных перед маппингом
        if (product.getName() != null) {
            product.setName(product.getName().trim());
        }
    }

    // ── @AfterMapping — действие после маппинга
    @AfterMapping
    default void afterMapping(Product product, @MappingTarget ProductResponse response) {
        // Например: добавить флаг скидки после маппинга
        response.setOnSale(product.getDiscount() != null
            && product.getDiscount().compareTo(BigDecimal.ZERO) > 0);
    }
}
4. uses — переиспользование маппера
Java
// ── Маппер для вложенного объекта
@Mapper(componentModel = "spring")
public interface AddressMapper {
    AddressResponse toResponse(Address address);
}

// ── Маппер использует AddressMapper для вложенного объекта
@Mapper(
    componentModel = "spring",
    uses = { AddressMapper.class }               // подключаем зависимый маппер
)
public interface UserMapper {

    // MapStruct автоматически использует AddressMapper для поля address
    UserResponse toResponse(User user);            // user.address → AddressResponse
}

// ── Маппер с несколькими зависимостями и пользовательскими Spring бинами
@Mapper(
    componentModel = "spring",
    uses = {
        AddressMapper.class,
        OrderItemMapper.class
    }
)
public interface OrderMapper {

    // ── Можно инжектировать Spring бины через @Autowired (не работает в record)
    @Autowired
    default UserRepository userRepository() { return null; }  // если нужен доступ к БД

    @Mapping(target = "customerName",
             expression = "java(order.getCustomer().getFirstName() + ' ' + order.getCustomer().getLastName())")
    @Mapping(target = "address", source = "deliveryAddress")  // переименование
    OrderResponse toResponse(Order order);                    // автоматически items
}
5. Маппинг с вложенными полями и enum
Java
// ── Сложный маппер с разными случаями
@Mapper(
    componentModel = "spring",
    nullValuePropertyMappingStrategy = NullValuePropertyMappingStrategy.IGNORE // игнорировать null при обновлении
)
public interface EmployeeMapper {

    // ── Вложенное поле: department.name → departmentName
    @Mapping(target = "departmentName", source = "department.name")   // точка — вложенный объект
    @Mapping(target = "managerEmail",   source = "department.manager.email") // глубокий путь

    // ── Константа — всегда устанавливать значение
    @Mapping(target = "source", constant = "INTERNAL")              // всегда "INTERNAL"

    // ── Default value — если поле null
    @Mapping(target = "status", source = "status", defaultValue = "ACTIVE") // если null → "ACTIVE"

    // ── Формат даты
    @Mapping(target = "birthDate", source = "birthDate", dateFormat = "dd.MM.yyyy")
    // преобразует LocalDate → String "15.01.1990"

    EmployeeResponse toResponse(Employee employee);

    // ── Маппинг Enum → другой Enum
    @ValueMappings({
        @ValueMapping(source = "FULL_TIME",  target = "FT"),          // EmploymentType.FULL_TIME → ContractType.FT
        @ValueMapping(source = "PART_TIME",  target = "PT"),
        @ValueMapping(source = MappingConstants.ANY_REMAINING, target = "OTHER") // всё остальное
    })
    ContractType toContractType(EmploymentType employmentType);

    // ── PATCH маппинг — игнорировать null поля (nullValuePropertyMappingStrategy = IGNORE)
    @Mapping(target = "id",        ignore = true)
    @Mapping(target = "createdAt", ignore = true)
    void patch(PatchEmployeeRequest request, @MappingTarget Employee employee);
    // null поля в request НЕ перезапишут поля employee (благодаря IGNORE стратегии)
}
6. Использование маппера в сервисе
Java
@Service
@RequiredArgsConstructor
@Slf4j
public class UserService {

    private final UserRepository userRepository;
    private final UserMapper     userMapper;      // Spring инжектирует UserMapperImpl
    private final PasswordEncoder passwordEncoder;

    // ── CREATE
    @Transactional
    public UserResponse create(CreateUserRequest request) {
        User user = userMapper.toEntity(request);  // DTO → Entity (без password/role)
        user.setPassword(passwordEncoder.encode(request.password())); // хэшируем пароль
        user.setRole(Role.ROLE_USER);              // устанавливаем роль
        User saved = userRepository.save(user);
        return userMapper.toResponse(saved);       // Entity → Response DTO
    }

    // ── READ ALL
    @Transactional(readOnly = true)
    public List<UserResponse> findAll() {
        return userMapper.toResponseList(userRepository.findAll()); // List Entity → List DTO
    }

    // ── UPDATE через @MappingTarget
    @Transactional
    public UserResponse update(Long id, UpdateUserRequest request) {
        User user = userRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("User", id));

        userMapper.updateEntity(request, user);   // обновляем поля Entity из DTO
        return userMapper.toResponse(user);        // dirty check сохранит изменения
    }

    // ── PATCH
    @Transactional
    public UserResponse patch(Long id, PatchUserRequest request) {
        User user = userRepository.findById(id)
            .orElseThrow(() -> new ResourceNotFoundException("User", id));

        userMapper.patch(request, user);           // null поля игнорируются!
        return userMapper.toResponse(user);
    }
}
❓ Вопросы для собеседования
Что такое MapStruct и чем он лучше ModelMapper?
What is MapStruct and how is it better than ModelMapper?
Medium▼
✅ Ответ
MapStruct — аннотационный процессор, генерирует обычный Java код (геттеры/сеттеры) на этапе компиляции. Никакой рефлексии в рантайме → скорость как ручной маппинг. Ошибки маппинга — на этапе компиляции (type-safe). ModelMapper использует рефлексию в рантайме — медленнее, ошибки только в рантайме, сложно отлаживать. Сгенерированный код MapStruct можно посмотреть в target/generated-sources.
Как обновить существующий Entity через MapStruct?
How do you update an existing entity using MapStruct?
Medium▼
✅ Ответ
Используем @MappingTarget на параметре метода. Метод с void возвратом принимает Request DTO и существующий Entity — MapStruct обновляет поля Entity из DTO. В сервисе: загружаем Entity из БД → вызываем mapper.updateEntity(request, entity) → JPA dirty checking сохраняет изменения при коммите транзакции. Для PATCH операций добавляем nullValuePropertyMappingStrategy = IGNORE чтобы null поля не перезаписывали существующие.
Почему Lombok должен быть перед MapStruct в annotationProcessorPaths?
Why must Lombok come before MapStruct in annotationProcessorPaths?
Hard▼
✅ Ответ
Lombok генерирует геттеры и сеттеры, MapStruct использует их для маппинга. Оба работают как аннотационные процессоры на этапе компиляции. Если MapStruct запустится раньше Lombok — геттеров ещё нет, маппинг не скомпилируется. Порядок в annotationProcessorPaths определяет порядок запуска процессоров. Lombok → затем MapStruct → MapStruct видит геттеры/сеттеры от Lombok.
Как в MapStruct замаппить вложенный объект в плоское поле?
How do you map a nested object property to a flat field in MapStruct?
Medium▼
✅ Ответ
Через точечную нотацию в source: @Mapping(source = "department.name", target = "departmentName"). MapStruct сгенерирует код который последовательно вызовет employee.getDepartment().getName() с null-проверкой на каждом уровне. Для обратного маппинга (плоское → вложенное) нужен отдельный кастомный метод или expression.
