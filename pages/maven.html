📌 Краткий конспект
Что такое Maven
Maven — инструмент сборки и управления зависимостями для Java проектов. Следует принципу «Convention over Configuration» — стандартная структура проекта работает без настройки. Центральный файл — pom.xml (Project Object Model).
КонцепцияОписание
POMProject Object Model — главный файл конфигурации
ArtifactРезультат сборки — JAR, WAR, ZIP
CoordinatesgroupId + artifactId + version — уникальный ID зависимости
RepositoryХранилище зависимостей (local ~/.m2, Central, Nexus)
PhaseШаг жизненного цикла (compile, test, package, install, deploy)
PluginРасширение Maven — выполняет задачи на фазах
GoalКонкретная задача плагина: compiler:compile
🔄 Жизненный цикл сборки

Maven имеет три встроенных жизненных цикла: default (сборка), clean (очистка), site (документация). Выполнение фазы запускает все предыдущие фазы автоматически.

Основной lifecycle (default)
#ФазаОписание
1validateПроверить что проект корректен
2compileСкомпилировать исходный код
3test-compileСкомпилировать тестовый код
4testЗапустить unit тесты
5packageУпаковать в JAR/WAR
6verifyЗапустить интеграционные проверки
7installУстановить в локальный репозиторий (~/.m2)
8deployЗагрузить в удалённый репозиторий (Nexus/Artifactory)
Схема: mvn package запускает все фазы до package
  mvn package
  │
  ├── validate      ← автоматически
  ├── compile       ← автоматически
  ├── test-compile  ← автоматически
  ├── test          ← автоматически
  └── package       ← целевая фаза → создаёт target/*.jar

  mvn install      ← включает все выше + копирует в ~/.m2
  mvn deploy       ← включает все выше + загружает в Nexus

Транзитивные зависимости

Maven автоматически подтягивает транзитивные зависимости. Для исключения конкретной используй <exclusions>. Для просмотра дерева зависимостей: mvn dependency:tree.

⚠️ Версионные конфликты
Если две зависимости требуют разные версии одной библиотеки — Maven использует «nearest wins» (ближайшая в дереве). Явно задай нужную версию в <dependencyManagement> или прямо в <dependencies>.

🎭 Maven Profiles

Profiles позволяют менять конфигурацию сборки для разных окружений или сценариев. Активируются через -P profile-name или автоматически по условию.

Способ активацииПример
Вручнуюmvn package -Pprod
По умолчанию<activation><activeByDefault>true</activeByDefault>
По OS<activation><os><name>Windows</name>
По JDK<activation><jdk>21</jdk>
По свойству<activation><property><name>env</name><value>prod</value>

✅ Best Practices
✅ Правильно
  • Использовать spring-boot-starter-parent как parent
  • Версии зависимостей в <properties>
  • Общие зависимости в <dependencyManagement> parent
  • Использовать mvnw (Maven Wrapper) — гарантирует версию
  • Отдельные scopes: test зависимости — scope=test
  • Явно задавать версию Java: maven.compiler.release
  • JaCoCo для coverage — проверять минимальный процент
  • maven-enforcer-plugin — запрещать конфликтные версии
🚫 Ошибки
  • Хардкодить версии зависимостей без properties
  • Использовать LATEST или RELEASE версии
  • Пропускать тесты в CI: -DskipTests в production
  • Коммитить .m2 локальный репозиторий
  • Дублировать зависимости в каждом модуле
  • Не управлять транзитивными зависимостями
💻 Примеры pom.xml
1. Полный pom.xml для Spring Boot проекта
XML — pom.xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0
         https://maven.apache.org/xsd/maven-4.0.0.xsd">

  <modelVersion>4.0.0</modelVersion>

  <!-- ── Родительский POM — управляет версиями зависимостей -->
  <parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.3.0</version>         <!-- версия Spring Boot -->
    <relativePath/>                    <!-- из Maven Central -->
  </parent>

  <!-- ── Координаты проекта -->
  <groupId>com.company</groupId>
  <artifactId>my-service</artifactId>
  <version>1.0.0-SNAPSHOT</version>  <!-- SNAPSHOT = в разработке -->
  <packaging>jar</packaging>
  <name>My Service</name>
  <description>My Spring Boot Microservice</description>

  <!-- ── Переменные версий -->
  <properties>
    <java.version>21</java.version>               <!-- версия Java -->
    <maven.compiler.release>21</maven.compiler.release>
    <mapstruct.version>1.5.5.Final</mapstruct.version>
    <lombok.version>1.18.30</lombok.version>
    <testcontainers.version>1.19.3</testcontainers.version>
    <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding>
  </properties>

  <!-- ── Зависимости -->
  <dependencies>

    <!-- Spring Boot стартеры -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-web</artifactId>
      <!-- версия не нужна — управляется parent -->
    </dependency>

    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-data-jpa</artifactId>
    </dependency>

    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-security</artifactId>
    </dependency>

    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-validation</artifactId>
    </dependency>

    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-actuator</artifactId>
    </dependency>

    <!-- База данных -->
    <dependency>
      <groupId>org.postgresql</groupId>
      <artifactId>postgresql</artifactId>
      <scope>runtime</scope>               <!-- runtime: нужен при запуске -->
    </dependency>

    <dependency>
      <groupId>org.flywaydb</groupId>
      <artifactId>flyway-core</artifactId>
    </dependency>

    <!-- JWT -->
    <dependency>
      <groupId>io.jsonwebtoken</groupId>
      <artifactId>jjwt-api</artifactId>
      <version>0.12.3</version>
    </dependency>
    <dependency>
      <groupId>io.jsonwebtoken</groupId>
      <artifactId>jjwt-impl</artifactId>
      <version>0.12.3</version>
      <scope>runtime</scope>
    </dependency>
    <dependency>
      <groupId>io.jsonwebtoken</groupId>
      <artifactId>jjwt-jackson</artifactId>
      <version>0.12.3</version>
      <scope>runtime</scope>
    </dependency>

    <!-- Lombok -->
    <dependency>
      <groupId>org.projectlombok</groupId>
      <artifactId>lombok</artifactId>
      <optional>true</optional>            <!-- не транзитивная -->
    </dependency>

    <!-- MapStruct -->
    <dependency>
      <groupId>org.mapstruct</groupId>
      <artifactId>mapstruct</artifactId>
      <version>${mapstruct.version}</version>
    </dependency>

    <!-- Тестирование (scope=test) -->
    <dependency>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-test</artifactId>
      <scope>test</scope>                  <!-- только для тестов -->
    </dependency>

    <dependency>
      <groupId>org.springframework.security</groupId>
      <artifactId>spring-security-test</artifactId>
      <scope>test</scope>
    </dependency>

    <!-- Testcontainers -->
    <dependency>
      <groupId>org.testcontainers</groupId>
      <artifactId>junit-jupiter</artifactId>
      <version>${testcontainers.version}</version>
      <scope>test</scope>
    </dependency>
    <dependency>
      <groupId>org.testcontainers</groupId>
      <artifactId>postgresql</artifactId>
      <version>${testcontainers.version}</version>
      <scope>test</scope>
    </dependency>

  </dependencies>

  <!-- ── Сборка и плагины -->
  <build>
    <plugins>

      <!-- Spring Boot плагин -->
      <plugin>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-maven-plugin</artifactId>
        <configuration>
          <excludes>
            <exclude>
              <groupId>org.projectlombok</groupId>  <!-- Lombok не нужен в fat JAR -->
              <artifactId>lombok</artifactId>
            </exclude>
          </excludes>
        </configuration>
      </plugin>

      <!-- Компилятор с аннотационными процессорами -->
      <plugin>
        <groupId>org.apache.maven.plugins</groupId>
        <artifactId>maven-compiler-plugin</artifactId>
        <configuration>
          <release>21</release>
          <annotationProcessorPaths>
            <path>
              <groupId>org.projectlombok</groupId>
              <artifactId>lombok</artifactId>
              <version>${lombok.version}</version>
            </path>
            <path>
              <groupId>org.mapstruct</groupId>
              <artifactId>mapstruct-processor</artifactId>
              <version>${mapstruct.version}</version>
            </path>
            <path>
              <groupId>org.projectlombok</groupId>
              <artifactId>lombok-mapstruct-binding</artifactId>
              <version>0.2.0</version>
            </path>
          </annotationProcessorPaths>
        </configuration>
      </plugin>

    </plugins>
  </build>

</project>
2. Exclusions и dependencyManagement
XML
<!-- ── Исключение транзитивной зависимости -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
  <exclusions>
    <exclusion>
      <groupId>org.springframework.boot</groupId>
      <artifactId>spring-boot-starter-tomcat</artifactId>  <!-- убрать Tomcat -->
    </exclusion>
  </exclusions>
</dependency>

<!-- Добавить Undertow вместо Tomcat -->
<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-undertow</artifactId>
</dependency>

<!-- ── dependencyManagement — управление версиями без добавления -->
<dependencyManagement>
  <dependencies>

    <!-- Импорт BOM (Bill of Materials) -->
    <dependency>
      <groupId>org.testcontainers</groupId>
      <artifactId>testcontainers-bom</artifactId>
      <version>${testcontainers.version}</version>
      <type>pom</type>
      <scope>import</scope>             <!-- import BOM -->
    </dependency>

    <!-- Фиксируем версию транзитивной зависимости -->
    <dependency>
      <groupId>org.yaml</groupId>
      <artifactId>snakeyaml</artifactId>
      <version>2.2</version>             <!-- фикс безопасности -->
    </dependency>

  </dependencies>
</dependencyManagement>
3. Profile для разных окружений
XML — profiles секция
<profiles>

  <!-- ── dev профиль (по умолчанию) -->
  <profile>
    <id>dev</id>
    <activation>
      <activeByDefault>true</activeByDefault> <!-- активен по умолчанию -->
    </activation>
    <properties>
      <spring.profiles.active>dev</spring.profiles.active>
    </properties>
    <dependencies>
      <dependency>                          <!-- H2 только в dev -->
        <groupId>com.h2database</groupId>
        <artifactId>h2</artifactId>
        <scope>runtime</scope>
      </dependency>
    </dependencies>
  </profile>

  <!-- ── prod профиль -->
  <profile>
    <id>prod</id>
    <properties>
      <spring.profiles.active>prod</spring.profiles.active>
    </properties>
    <build>
      <plugins>
        <plugin>                            <!-- JaCoCo в prod build -->
          <groupId>org.jacoco</groupId>
          <artifactId>jacoco-maven-plugin</artifactId>
          <version>0.8.11</version>
          <executions>
            <execution>
              <goals><goal>prepare-agent</goal></goals>
            </execution>
            <execution>
              <id>report</id>
              <phase>verify</phase>
              <goals><goal>report</goal></goals>
            </execution>
          </executions>
        </plugin>
      </plugins>
    </build>
  </profile>

</profiles>
❓ Вопросы для собеседования
Что такое Maven жизненный цикл? Какие основные фазы?
What is the Maven build lifecycle and what are the main phases?
Easy▼
✅ Ответ
Жизненный цикл — последовательность фаз сборки. Основные фазы default lifecycle: validate → compile → test → package → install → deploy. Каждая фаза выполняет все предыдущие автоматически. mvn package компилирует, запускает тесты и создаёт JAR. mvn install дополнительно копирует в локальный ~/.m2. mvn deploy загружает в Nexus/Artifactory.
Какие scope зависимостей ты знаешь?
What Maven dependency scopes do you know?
Medium▼
✅ Ответ
compile (default) — нужен везде, включается в JAR.
provided — нужен при компиляции, не включается в JAR (сервер предоставит, например servlet-api).
runtime — не нужен при компиляции, нужен при запуске (JDBC драйвер).
test — только для тестов (JUnit, Mockito, Testcontainers).
import — только в dependencyManagement, импорт BOM.
Чем dependencyManagement отличается от dependencies?
What is the difference between dependencyManagement and dependencies?
Medium▼
✅ Ответ
<dependencies> — реально добавляет зависимость в classpath.
<dependencyManagement> — только управляет версиями, НЕ добавляет зависимость. Дочерние POM'ы могут подключить зависимость без указания версии — версия берётся из dependencyManagement родителя. Используется в multi-module проектах для централизованного управления версиями и при импорте BOM (scope=import).
Зачем нужен Maven Wrapper (mvnw)?
What is Maven Wrapper and why is it used?
Easy▼
✅ Ответ
Maven Wrapper (mvnw) — скрипт который автоматически скачивает нужную версию Maven если она не установлена. Гарантирует что все разработчики и CI/CD используют одну и ту же версию Maven. Файлы: mvnw (Linux/Mac), mvnw.cmd (Windows), .mvn/wrapper/maven-wrapper.properties. Лучшая практика — коммитить mvnw в репозиторий и использовать ./mvnw вместо mvn.
