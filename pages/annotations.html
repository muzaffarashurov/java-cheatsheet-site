❓ Вопросы для собеседования
В чём разница между @Component, @Service, @Repository и @Controller?
What is the difference between @Component, @Service, @Repository, and @Controller?
Easy▼
✅ Ответ
Все четыре — специализации @Component и регистрируют бин в Spring контейнере. Различия: @Repository дополнительно переводит исключения БД в Spring DataAccessException. @Service и @Controller — чисто семантические, говорят о роли класса. Используй по назначению — это помогает читаемости и позволяет AOP таргетировать слои.
Что делает @Transactional и когда он не работает?
What does @Transactional do and when does it not work?
Medium▼
✅ Ответ
@Transactional создаёт AOP прокси: открывает транзакцию до вызова метода, коммитит при успехе, откатывает при RuntimeException. Не работает когда: 1) вызов из того же класса (self-invocation — прокси минуется), 2) метод private (Spring AOP не может создать прокси), 3) не Spring бин (обычный new Object()), 4) checked исключение без rollbackFor = Exception.class.
Зачем нужен @RequiredArgsConstructor от Lombok?
What is @RequiredArgsConstructor from Lombok used for?
Easy▼
✅ Ответ
@RequiredArgsConstructor генерирует конструктор для всех полей помеченных final или @NonNull. В Spring это позволяет использовать constructor injection без явного написания конструктора. Вместе с private final UserRepository repo; Lombok автоматически создаёт public UserService(UserRepository repo) { this.repo = repo; } — стандартный DI через конструктор без бойлерплейта.
Чем @SpringBootTest отличается от @WebMvcTest?
What is the difference between @SpringBootTest and @WebMvcTest?
Medium▼
✅ Ответ
@SpringBootTest загружает полный ApplicationContext — все слои, БД, реальные бины. Медленнее, нужен для интеграционных тестов. @WebMvcTest(UserController.class) загружает только Web слой (контроллеры, фильтры, конфигурации MVC) — без репозиториев и сервисов. Быстрее, для unit-тестов контроллеров. Сервисы мокируются через @MockBean.
Что такое @FetchType.LAZY и почему это важно?
What is FetchType.LAZY and why does it matter?
Medium▼
✅ Ответ
LAZY — связанные сущности загружаются только при первом обращении. EAGER — загружаются сразу вместе с основной сущностью. По умолчанию: @OneToMany и @ManyToMany — LAZY, @ManyToOne и @OneToOne — EAGER. Важно: LAZY лучше по производительности (не грузим лишнее), но обращение к LAZY коллекции вне транзакции вызовет LazyInitializationException. Решения: JOIN FETCH в JPQL, @EntityGraph, или использовать DTO проекции.
