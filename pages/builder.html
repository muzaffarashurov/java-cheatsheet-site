📌 Краткий конспект
Зачем Builder паттерн
Когда у класса много параметров — конструктор нечитаем: new User(1L, "Ivan", null, true, "ADMIN", ...). Builder делает создание объекта читаемым и безопасным: User.builder().id(1L).name("Ivan").role("ADMIN").build().

🏗 Builder Pattern — суть

Builder — порождающий паттерн. Позволяет создавать сложные объекты пошагово. Отделяет конструкцию от представления.

❌ Без Builder
  • Telescoping constructor антипаттерн
  • new User("Ivan", null, null, true, "ADMIN")
  • Непонятно что означает каждый аргумент
  • Легко перепутать порядок параметров
  • При добавлении поля — всё ломается
✅ С Builder
  • Явное именование каждого поля
  • User.builder().name("Ivan").role("ADMIN").build()
  • Необязательные поля можно пропустить
  • Порядок не важен
  • Читаемый, самодокументирующийся код

⚠️ Lombok + JPA Entity — подводные камни
🚫 Не используй @Data на JPA Entity
@Data генерирует equals() и hashCode() по всем полям включая lazy-loaded связи. Это вызывает рекурсию, N+1 запросов, и LazyInitializationException. Также @Data генерирует сеттеры — Entity должна контролировать своё состояние.
🚫 Плохо для Entity
  • @Data — equals/hashCode по всем полям
  • @EqualsAndHashCode без ограничений
  • @ToString включая lazy коллекции
  • @AllArgsConstructor без @NoArgsConstructor
✅ Правильно для Entity
  • @Getter — только геттеры
  • @Setter — только там где нужно
  • @EqualsAndHashCode(of = {"id"}) — только по PK
  • @ToString(exclude = {"orders"}) — исключить связи
  • @NoArgsConstructor + @AllArgsConstructor
  • @Builder — для удобного создания
✅ Best Practices
✅ Правильно
  • @RequiredArgsConstructor для DI в Spring
  • @Slf4j для логирования
  • @Builder для сложных объектов
  • Для Entity: @Getter @Setter @NoArgsConstructor
  • Для DTO: используй record вместо Lombok
  • @Builder.Default для дефолтных значений
  • toBuilder = true для создания копий с изменениями
🚫 Ошибки
  • @Data на JPA Entity
  • @ToString без exclude на lazy связях
  • @EqualsAndHashCode по всем полям в Entity
  • Смешивать @Builder с @NoArgsConstructor без @AllArgsConstructor
  • Не добавлять @NoArgsConstructor к Entity с @Builder
💻 Примеры кода
1. Builder паттерн вручную
Java
// ── Класс с приватным конструктором
public class User {
    private final Long    id;          // все поля final — immutable
    private final String  name;
    private final String  email;
    private final String  role;
    private final boolean active;

    // Приватный конструктор — только через Builder
    private User(Builder builder) {
        this.id     = builder.id;
        this.name   = builder.name;
        this.email  = builder.email;
        this.role   = builder.role;
        this.active = builder.active;
    }

    // Геттеры
    public Long    getId()    { return id;     }
    public String  getName()  { return name;   }
    public String  getEmail() { return email;  }
    public String  getRole()  { return role;   }
    public boolean isActive() { return active;  }

    // Статический метод — точка входа в Builder
    public static Builder builder() { return new Builder(); }

    // ── Статический inner class Builder
    public static class Builder {
        private Long    id;
        private String  name;
        private String  email;
        private String  role   = "USER";    // значение по умолчанию
        private boolean active = true;      // значение по умолчанию

        public Builder id(Long id)         { this.id     = id;     return this; } // return this — цепочка
        public Builder name(String name)   { this.name   = name;   return this; }
        public Builder email(String email) { this.email  = email;  return this; }
        public Builder role(String role)   { this.role   = role;   return this; }
        public Builder active(boolean a)  { this.active = a;      return this; }

        public User build() {
            // валидация перед созданием
            if (name == null || name.isBlank()) {
                throw new IllegalStateException("name обязателен");
            }
            return new User(this);              // создаём объект
        }
    }
}

// ── Использование
User user = User.builder()
    .id(1L)
    .name("Иван Иванов")
    .email("ivan@mail.ru")
    .role("ADMIN")                           // опционально — есть дефолт "USER"
    .build();                                 // создать объект

// active не указан — будет true (дефолт)
2. @Builder Lombok — все возможности
Java
// ── Базовый @Builder
@Builder                                          // генерирует builder() и Builder class
@Getter                                           // геттеры для всех полей
@ToString                                         // toString()
public class UserDto {
    private Long   id;
    private String name;
    private String email;

    @Builder.Default                              // дефолтное значение в Builder
    private String role = "USER";               // без @Builder.Default — будет null

    @Builder.Default
    private boolean active = true;

    @Builder.Default
    private List<String> tags = new ArrayList<>(); // пустой список по умолчанию
}

// ── Использование
UserDto user = UserDto.builder()
    .id(42L)
    .name("Иван")
    .email("ivan@mail.ru")
    // role = "USER" (дефолт), active = true (дефолт)
    .build();

// ── @Builder с toBuilder — создание копии с изменениями
@Builder(toBuilder = true)                       // добавляет метод toBuilder()
@Getter
public class OrderDto {
    private Long   id;
    private String status;
    private BigDecimal total;
}

OrderDto original = OrderDto.builder()
    .id(1L).status("PENDING").total(BigDecimal.valueOf(100)).build();

OrderDto updated = original.toBuilder()         // копируем все поля
    .status("COMPLETED")                         // меняем только status
    .build();                                     // id и total остаются прежними

// ── @Singular — добавлять элементы коллекции по одному
@Builder
@Getter
public class RoleRequest {
    private String username;

    @Singular                                     // метод role() вместо roles()
    private List<String> roles;
}

RoleRequest req = RoleRequest.builder()
    .username("ivan")
    .role("ADMIN")                              // добавляем по одному
    .role("MODERATOR")
    .role("USER")
    .build();
// roles = ["ADMIN", "MODERATOR", "USER"]
3. JPA Entity с Lombok — правильно
Java
@Entity
@Table(name = "users")
@Getter                                           // геттеры для всех полей
@Setter                                           // сеттеры (или только для нужных полей)
@NoArgsConstructor                                // ОБЯЗАТЕЛЕН для JPA!
@AllArgsConstructor                               // нужен для @Builder
@Builder                                          // удобное создание
// НЕ @Data — опасно для Entity!
@ToString(exclude = {"orders", "addresses"})   // исключаем lazy коллекции
@EqualsAndHashCode(of = "id")                   // только по id — безопасно
public class User {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false)
    private String name;

    @Column(unique = true, nullable = false)
    private String email;

    private String password;

    @Enumerated(EnumType.STRING)
    private Role role;

    @Builder.Default
    private boolean active = true;

    @CreationTimestamp
    private Instant createdAt;

    // Связи — НЕ включаем в @ToString!
    @OneToMany(mappedBy = "user", fetch = FetchType.LAZY)
    private List<Order> orders = new ArrayList<>();
}

// ── Использование
User user = User.builder()
    .name("Иван Иванов")
    .email("ivan@mail.ru")
    .password(passwordEncoder.encode("secret"))
    .role(Role.ROLE_USER)
    .build();                                     // active = true (дефолт)
4. @RequiredArgsConstructor и @Slf4j в сервисе
Java
@Service
@RequiredArgsConstructor                          // конструктор для всех final полей
@Slf4j                                            // создаёт поле: private static final Logger log = ...
public class UserService {

    // final + @RequiredArgsConstructor = DI через конструктор без @Autowired
    private final UserRepository  userRepository;  // инжектируется автоматически
    private final UserMapper      userMapper;
    private final PasswordEncoder passwordEncoder;

    // НЕ final — не инжектируется конструктором
    private String someOptionalValue;

    public UserResponse create(CreateUserRequest request) {
        log.info("Создание пользователя: email={}", request.email()); // SLF4J логгер
        log.debug("Полный запрос: {}", request);

        User user = User.builder()
            .name(request.name())
            .email(request.email())
            .password(passwordEncoder.encode(request.password()))
            .role(Role.ROLE_USER)
            .build();

        User saved = userRepository.save(user);
        log.info("Пользователь создан: id={}", saved.getId());
        return userMapper.toResponse(saved);
    }
}

5. @SuperBuilder — Builder с наследованием
Java
// ── Базовый класс с @SuperBuilder
@SuperBuilder                                     // НЕ @Builder — для иерархий
@Getter
public class BaseEntity {
    private Long    id;
    private Instant createdAt;
    private Instant updatedAt;
}

// ── Наследник тоже с @SuperBuilder
@SuperBuilder                                     // обязателен на всей иерархии
@Getter
public class ProductEntity extends BaseEntity {
    private String     name;
    private BigDecimal price;
    private String     category;
}

// ── Использование — доступны поля из ОБОИХ классов
ProductEntity product = ProductEntity.builder()
    .id(1L)                                      // поле BaseEntity
    .createdAt(Instant.now())                    // поле BaseEntity
    .name("Ноутбук")                             // поле ProductEntity
    .price(BigDecimal.valueOf(75000))            // поле ProductEntity
    .build();

// ── Обычный @Builder НЕ работает с наследованием!
// @Builder на ProductEntity не видит поля BaseEntity
❓ Вопросы для собеседования
Зачем нужен Builder паттерн?
What is the Builder pattern and why is it used?
Easy▼
✅ Ответ
Builder решает проблему «telescoping constructor» — когда у класса много параметров, конструктор нечитаем: непонятно что значит каждый аргумент, легко перепутать порядок. Builder позволяет создавать объект пошагово с именованными полями, пропускать необязательные поля, задавать дефолтные значения, и валидировать в методе build(). С Lombok — @Builder делает всё это одной аннотацией.
Почему нельзя использовать @Data на JPA Entity?
Why shouldn't you use @Data on a JPA Entity?
Medium▼
✅ Ответ
@Data генерирует equals()/hashCode() по всем полям включая lazy-loaded коллекции. Это вызывает: 1) LazyInitializationException если сессия закрыта, 2) N+1 проблему при сравнении, 3) рекурсию если двусторонние связи. Также @Data генерирует @ToString с ленивыми связями — аналогичные проблемы. Для Entity используй отдельные аннотации: @Getter @Setter @EqualsAndHashCode(of="id") @ToString(exclude={"коллекции"}).
Чем @Builder отличается от @SuperBuilder?
What is the difference between @Builder and @SuperBuilder?
Medium▼
✅ Ответ
@Builder не поддерживает наследование — Builder дочернего класса не видит поля родителя. @SuperBuilder — специальная версия для иерархий классов, поддерживает поля как родительского, так и дочернего класса в одном Builder'е. Требует наличия @SuperBuilder на всей иерархии. Используй @SuperBuilder когда есть наследование в классах с Builder'ом.
Зачем @RequiredArgsConstructor для DI в Spring?
Why use @RequiredArgsConstructor for Spring DI?
Easy▼
✅ Ответ
@RequiredArgsConstructor генерирует конструктор для всех final и @NonNull полей. Это позволяет использовать constructor injection в Spring без явного @Autowired (Spring 4.3+ автоматически использует единственный конструктор). Плюсы: поля final (immutable), зависимости явные, легко тестировать (просто передать мок в конструктор), Lombok убирает бойлерплейт конструктора.
