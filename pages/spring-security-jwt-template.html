Spring Security JWT Protection — Ready-Made Template

Универсальный модуль аутентификации с JWT: регистрация, логин, роли, фильтрация запросов. Копируй папку security/ в любой проект — работает из коробки.

📌 Краткий конспект

JWT Flow — как работает аутентификация
Клиент → POST /api/auth/login (username/password) → AuthService → AuthenticationManager → JwtService → Token → Клиент хранит токен → Следующие запросы с Authorization: Bearer <token> → JwtAuthenticationFilter проверяет токен → доступ к защищённым ресурсам
КомпонентЗадачаКлючевые аннотацииВозвращает
AuthControllerПриём /login, /register@RestController, @RequestMappingJwtResponse / String
AuthServiceБизнес-логика аутентификации@Service, @TransactionalJwtResponse / void
JwtServiceГенерация/валидация JWT@Service, @Slf4jString / boolean
UserDetailsServiceЗагрузка пользователя из БД@Service, @TransactionalUserDetails
SecurityConfigНастройка SecurityFilterChain@Configuration, @EnableWebSecuritySecurityFilterChain
JwtAuthenticationFilterПерехват запросов, проверка токена@Component, OncePerRequestFiltervoid (фильтр)

📦 Шаг 1: Зависимости (pom.xml)

Добавь эти зависимости в <dependencies> твоего pom.xml. Maven автоматически скачает все библиотеки.

pom.xml — добавить в <dependencies> 
<!-- SPRING SECURITY — основа аутентификации и авторизации -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>

<!-- JJWT API — интерфейс для работы с JWT (генерация, парсинг) -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.6</version>
</dependency>

<!-- JJWT Implementation — реальная реализация (нужна при запуске) -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>  <!-- только при запуске, не при компиляции -->
</dependency>

<!-- JJWT Jackson — сериализация payload в JSON -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-jackson</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>
</dependency>

<!-- VALIDATION — аннотации @NotBlank, @Email для DTO -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>

⚙️ Шаг 2: Конфигурация JWT (application.yml)

💡 Безопасность секрета
${JWT_SECRET:...} берёт значение из переменной окружения. В продакшене никогда не храни секрет в коде — используй Vault, Kubernetes Secrets или CI/CD переменные.
application.yml — добавить блок app.jwt 
# =====================================================================
# JWT настройки — секрет и время жизни токена
# =====================================================================
app:
  jwt:
    # Секретный ключ для подписи токенов
    # ${JWT_SECRET:...} — берёт из переменной окружения, или дефолтное значение
    # Минимальная длина: 256 бит (32 байта) для HS256
    secret: ${JWT_SECRET:mySuperSecretKeyForJwtTokenThatShouldBeVeryLongAndSecureAtLeast256Bits1234567890abcdef}
    
    # Время жизни токена в миллисекундах
    # 86400000 ms = 24 часа
    expiration-ms: 86400000

👤 Шаг 4: Entity (User / Role)

🔗 ManyToMany связь
@JoinTable создаёт промежуточную таблицу user_roles. Один пользователь может иметь несколько ролей, одна роль — у многих пользователей.
security/entity/Role.java
package com.example.employee.security.entity;

import jakarta.persistence.*;
import lombok.*;

@Entity
@Table(name = "roles")
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class Role {
    
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    /*
     * @Column(unique = true) — роль не может дублироваться.
     * Примеры: ROLE_ADMIN, ROLE_USER, ROLE_MANAGER
     */
    @Column(nullable = false, unique = true, length = 50)
    private String name;
}
security/entity/User.java
package com.example.employee.security.entity;

import jakarta.persistence.*;
import lombok.*;
import java.time.LocalDateTime;
import java.util.HashSet;
import java.util.Set;

@Entity
@Table(name = "users")
@Data
@NoArgsConstructor
@AllArgsConstructor
@Builder
public class User {
    
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 50)
    private String username;

    /*
     * Пароль ВСЕГДА хранится в захешированном виде (BCrypt).
     * Никогда не сохраняй пароли в открытом виде!
     */
    @Column(nullable = false, length = 255)
    private String password;

    @Column(nullable = false, unique = true, length = 150)
    private String email;

    @Column(name = "first_name", nullable = false, length = 100)
    private String firstName;

    @Column(name = "last_name", nullable = false, length = 100)
    private String lastName;

    @Column(nullable = false)
    private boolean enabled = true;

    @Column(name = "created_at", nullable = false, updatable = false)
    private LocalDateTime createdAt;

    /*
     * ManyToMany связь с ролями через промежуточную таблицу user_roles.
     * fetch = EAGER — загружать роли сразу при загрузке пользователя
     * (нужно для авторизации в одном запросе).
     */
    @ManyToMany(fetch = FetchType.EAGER)
    @JoinTable(
        name = "user_roles",
        joinColumns = @JoinColumn(name = "user_id"),
        inverseJoinColumns = @JoinColumn(name = "role_id")
    )
    @Builder.Default
    private Set<Role> roles = new HashSet<>();

    @PrePersist
    protected void onCreate() {
        this.createdAt = LocalDateTime.now();
    }
}

🔐 Шаг 7: JwtService (генерация и валидация токенов)

⚠️ Безопасность ключа
Метод key() кодирует секрет через Base64 дважды — это защита от случайного использования слабого ключа. В продакшене используй минимум 256-битный ключ.
security/service/JwtService.java
package com.example.employee.security.service;

import io.jsonwebtoken.*;
import io.jsonwebtoken.io.Decoders;
import io.jsonwebtoken.security.Keys;
import lombok.extern.slf4j.Slf4j;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.stereotype.Service;
import javax.crypto.SecretKey;
import java.util.Date;
import java.util.stream.Collectors;

@Service
@Slf4j
public class JwtService {
    
    /*
     * @Value читает настройки из application.yml:
     *   ${app.jwt.secret} — секретный ключ
     *   ${app.jwt.expiration-ms} — время жизни токена
     */
    @Value("${app.jwt.secret}")
    private String jwtSecret;

    @Value("${app.jwt.expiration-ms}")
    private long jwtExpirationMs;

    /*
     * key() — создаёт SecretKey для подписи/верификации токенов.
     * Используем HMAC-SHA алгоритм (быстрый и безопасный).
     *
     * Двойное кодирование Base64 — защита от слабых ключей:
     *   1. jwtSecret.getBytes() → байты
     *   2. Base64.encode() → строка
     *   3. Decoders.BASE64.decode() → байты для Keys.hmacShaKeyFor()
     */
    private SecretKey key() {
        return Keys.hmacShaKeyFor(
            Decoders.BASE64.decode(
                java.util.Base64.getEncoder().encodeToString(jwtSecret.getBytes())
            )
        );
    }

    /*
     * generateToken — создаёт JWT после успешной аутентификации.
     *
     * Payload токена содержит:
     *   sub (subject) — username
     *   roles — список ролей через запятую
     *   iat (issued at) — время создания
     *   exp (expiration) — время истечения
     *
     * Подпись: .signWith(key()) — HMAC-SHA256
     */
    public String generateToken(Authentication authentication) {
        String username = authentication.getName();
        
        /*
         * Собираем роли в строку: "ROLE_USER,ROLE_ADMIN"
         * Это нужно, чтобы не хранить сложные объекты в токене.
         */
        String authorities = authentication.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .collect(Collectors.joining(","));

        Date now = new Date();
        Date expiryDate = new Date(now.getTime() + jwtExpirationMs);

        return Jwts.builder()
            .subject(username)
            .claim("roles", authorities)
            .issuedAt(now)
            .expiration(expiryDate)
            .signWith(key())
            .compact();
    }

    /*
     * getUsernameFromToken — извлекает username из токена.
     * Используется в JwtAuthenticationFilter для аутентификации.
     */
    public String getUsernameFromToken(String token) {
        return parseToken(token).getSubject();
    }

    /*
     * getRolesFromToken — извлекает строку ролей из токена.
     */
    public String getRolesFromToken(String token) {
        return parseToken(token).get("roles", String.class);
    }

    /*
     * parseToken — внутренний метод для парсинга и верификации.
     * .verifyWith(key()) — проверяет подпись токена.
     * .parseSignedClaims() — разбирает payload после проверки.
     */
    private Claims parseToken(String token) {
        return Jwts.parser()
            .verifyWith(key())
            .build()
            .parseSignedClaims(token)
            .getPayload();
    }

    /*
     * validateToken — полная проверка токена на валидность.
     * Ловит все возможные исключения JJWT и логирует их.
     *
     * Возвращает true только если токен:
     *   ✓ Подписан правильным ключом
     *   ✓ Не истёк
     *   ✓ Корректно сформирован
     */
    public boolean validateToken(String token) {
        try {
            parseToken(token);
            return true;
        } catch (ExpiredJwtException e) {
            log.error("JWT просрочен: {}", e.getMessage());
        } catch (UnsupportedJwtException e) {
            log.error("JWT неподдерживаемый: {}", e.getMessage());
        } catch (MalformedJwtException e) {
            log.error("JWT повреждён: {}", e.getMessage());
        } catch (SecurityException e) {
            log.error("JWT подпись невалидна: {}", e.getMessage());
        } catch (IllegalArgumentException e) {
            log.error("JWT пустой: {}", e.getMessage());
        }
        return false;
    }
}

👤 Шаг 8: UserDetails (адаптер для Spring Security)

UserDetailsImpl — мост между нашей User-entity и Spring Security. Реализует интерфейс org.springframework.security.core.userdetails.UserDetails.

security/service/UserDetailsImpl.java
package com.example.employee.security.service;

import com.example.employee.security.entity.User;
import com.fasterxml.jackson.annotation.JsonIgnore;
import lombok.AllArgsConstructor;
import lombok.Data;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.authority.SimpleGrantedAuthority;
import org.springframework.security.core.userdetails.UserDetails;
import java.util.Collection;
import java.util.List;
import java.util.stream.Collectors;

@Data
@AllArgsConstructor
public class UserDetailsImpl implements UserDetails {
    
    private static final long serialVersionUID = 1L;

    private Long id;
    private String username;
    private String email;

    /*
     * @JsonIgnore — не сериализовать пароль в JSON-ответах.
     * Даже если случайно вернёшь UserDetails клиенту — пароль не утечёт.
     */
    @JsonIgnore
    private String password;

    private Collection<? extends GrantedAuthority> authorities;
    private boolean enabled;

    /*
     * build() — фабричный метод для конвертации User → UserDetailsImpl.
     * Преобразует Set<Role> в Collection<GrantedAuthority>.
     *
     * SimpleGrantedAuthority("ROLE_ADMIN") — формат, который понимает
     * Spring Security для проверки hasRole("ADMIN").
     */
    public static UserDetailsImpl build(User user) {
        List<GrantedAuthority> authorities = user.getRoles().stream()
            .map(role -> new SimpleGrantedAuthority(role.getName()))
            .collect(Collectors.toList());

        return new UserDetailsImpl(
            user.getId(),
            user.getUsername(),
            user.getEmail(),
            user.getPassword(),
            authorities,
            user.getEnabled()
        );
    }

    // === Реализация интерфейса UserDetails ===
    @Override
    public Collection<? extends GrantedAuthority> getAuthorities() {
        return authorities;
    }

    @Override
    public String getPassword() {
        return password;
    }

    @Override
    public String getUsername() {
        return username;
    }

    /*
     * Эти 4 метода можно кастомизировать:
     *   - Блокировка аккаунта после N неудачных попыток
     *   - Принудительная смена пароля
     *   - Временная деактивация
     * По умолчанию — всегда true (аккаунт активен).
     */
    @Override
    public boolean isAccountNonExpired() {
        return true;
    }

    @Override
    public boolean isAccountNonLocked() {
        return true;
    }

    @Override
    public boolean isCredentialsNonExpired() {
        return true;
    }

    @Override
    public boolean isEnabled() {
        return enabled;
    }
}
security/service/UserDetailsServiceImpl.java
package com.example.employee.security.service;

import com.example.employee.security.entity.User;
import com.example.employee.security.repository.UserRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.core.userdetails.UserDetails;
import org.springframework.security.core.userdetails.UserDetailsService;
import org.springframework.security.core.userdetails.UsernameNotFoundException;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@RequiredArgsConstructor
@Slf4j
public class UserDetailsServiceImpl implements UserDetailsService {
    
    private final UserRepository userRepository;

    /*
     * loadUserByUsername — главный метод Spring Security для загрузки пользователя.
     * Вызывается при логине и при проверке каждого защищённого запроса.
     *
     * @Transactional(readOnly = true) — оптимизация: только чтение из БД.
     * Hibernate отключает dirty checking, что ускоряет запрос.
     *
     * UsernameNotFoundException — стандартное исключение, которое
     * Spring Security перехватывает и возвращает 401 Unauthorized.
     */
    @Override
    @Transactional(readOnly = true)
    public UserDetails loadUserByUsername(String username) throws UsernameNotFoundException {
        User user = userRepository.findByUsername(username)
            .orElseThrow(() -> new UsernameNotFoundException(
                "User not found: " + username
            ));
        return UserDetailsImpl.build(user);
    }
}

⚙️ Шаг 9: AuthService (бизнес-логика аутентификации)

🔐 Хэширование паролей
passwordEncoder.encode() использует BCrypt — адаптивный алгоритм, который автоматически становится медленнее с ростом мощности железа. Это защита от брутфорса.
security/service/AuthService.java
package com.example.employee.security.service;

import com.example.employee.security.dto.JwtResponse;
import com.example.employee.security.dto.LoginRequest;
import com.example.employee.security.dto.SignupRequest;
import com.example.employee.security.entity.Role;
import com.example.employee.security.entity.User;
import com.example.employee.security.repository.RoleRepository;
import com.example.employee.security.repository.UserRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.UsernamePasswordAuthenticationToken;
import org.springframework.security.core.Authentication;
import org.springframework.security.core.GrantedAuthority;
import org.springframework.security.core.context.SecurityContextHolder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;
import java.util.HashSet;
import java.util.List;
import java.util.Set;
import java.util.stream.Collectors;

@Service
@RequiredArgsConstructor
@Slf4j
public class AuthService {
    
    private final AuthenticationManager authenticationManager;
    private final UserRepository userRepository;
    private final RoleRepository roleRepository;
    private final PasswordEncoder passwordEncoder;
    private final JwtService jwtService;

    // ==================== АУТЕНТИФИКАЦИЯ (ЛОГИН) ====================

    /*
     * authenticate — основной метод для входа пользователя.
     *
     * 1. AuthenticationManager проверяет username/password
     *    (использует UserDetailsServiceImpl + PasswordEncoder)
     * 2. При успехе — сохраняем аутентификацию в SecurityContext
     * 3. Генерируем JWT токен через JwtService
     * 4. Возвращаем JwtResponse с токеном и данными пользователя
     */
    @Transactional
    public JwtResponse authenticate(LoginRequest request) {
        
        // Шаг 1: Проверка учётных данных
        Authentication authentication = authenticationManager.authenticate(
            new UsernamePasswordAuthenticationToken(
                request.getUsername(), 
                request.getPassword()
            )
        );

        // Шаг 2: Сохраняем в контекст (нужно для генерации токена)
        SecurityContextHolder.getContext().setAuthentication(authentication);

        // Шаг 3: Генерируем JWT
        String jwt = jwtService.generateToken(authentication);

        // Шаг 4: Собираем ответ
        UserDetailsImpl userDetails = (UserDetailsImpl) authentication.getPrincipal();
        List<String> roles = userDetails.getAuthorities().stream()
            .map(GrantedAuthority::getAuthority)
            .collect(Collectors.toList());

        return new JwtResponse(
            "Bearer", jwt, userDetails.getId(),
            userDetails.getUsername(), userDetails.getEmail(), roles
        );
    }

    // ==================== РЕГИСТРАЦИЯ ====================

    /*
     * register — создание нового пользователя.
     *
     * 1. Проверяем уникальность username/email
     * 2. Хэшируем пароль через BCrypt
     * 3. Назначаем роли (по умолчанию ROLE_USER)
     * 4. Сохраняем в БД
     *
     * @Transactional — атомарность: если ошибка на любом шаге,
     * все изменения откатываются (ROLLBACK).
     */
    @Transactional
    public void register(SignupRequest request) {
        
        // Проверка уникальности
        if (userRepository.existsByUsername(request.getUsername())) {
            throw new IllegalArgumentException(
                "Username already taken: " + request.getUsername()
            );
        }
        if (userRepository.existsByEmail(request.getEmail())) {
            throw new IllegalArgumentException(
                "Email already taken: " + request.getEmail()
            );
        }

        // Создание пользователя
        User user = User.builder()
            .username(request.getUsername())
            .password(passwordEncoder.encode(request.getPassword()))  // 🔐 BCrypt!
            .email(request.getEmail())
            .firstName(request.getFirstName())
            .lastName(request.getLastName())
            .enabled(true)
            .build();

        // Назначение ролей
        Set<Role> roles = new HashSet<>();
        
        if (request.getRoles() == null || request.getRoles().isEmpty()) {
            // По умолчанию — обычная роль пользователя
            Role userRole = roleRepository.findByName("ROLE_USER")
                .orElseThrow(() -> new RuntimeException("ROLE_USER not found"));
            roles.add(userRole);
        } else {
            // Клиент указал конкретные роли
            request.getRoles().forEach(roleStr -> {
                String roleName = roleStr.startsWith("ROLE_") 
                    ? roleStr 
                    : "ROLE_" + roleStr.toUpperCase();
                
                Role role = roleRepository.findByName(roleName)
                    .orElseThrow(() -> new RuntimeException(
                        "Role not found: " + roleName
                    ));
                roles.add(role);
            });
        }

        user.setRoles(roles);
        userRepository.save(user);
    }
}

🛡️ Шаг 10: SecurityConfig (настройка безопасности)

⚠️ CSRF и Stateless
.csrf(AbstractHttpConfigurer::disable) — отключаем CSRF для JWT-аутентификации (токен в заголовке, не в cookie). SessionCreationPolicy.STATELESS — сервер не хранит сессии, каждый запрос аутентифицируется отдельно.
security/SecurityConfig.java
package com.example.employee.security;

import com.example.employee.security.service.UserDetailsServiceImpl;
import lombok.RequiredArgsConstructor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.security.authentication.AuthenticationManager;
import org.springframework.security.authentication.AuthenticationProvider;
import org.springframework.security.authentication.dao.DaoAuthenticationProvider;
import org.springframework.security.config.annotation.authentication.configuration.AuthenticationConfiguration;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configuration.EnableWebSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;
import org.springframework.security.web.authentication.UsernamePasswordAuthenticationFilter;

@Configuration
@EnableWebSecurity
@EnableMethodSecurity(prePostEnabled = true, securedEnabled = true, jsr250Enabled = true)
@RequiredArgsConstructor
public class SecurityConfig {
    
    private final JwtAuthenticationFilter jwtAuthFilter;
    private final UserDetailsServiceImpl userDetailsService;

    /*
     * filterChain — главная настройка безопасности приложения.
     * Определяет: какие URL открыты, какие защищены, какие фильтры применять.
     *
     * Порядок правил ВАЖЕН: первое совпадение побеждает.
     */
    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        
        http
            // 1. Отключаем CSRF для stateless JWT-аутентификации
            .csrf(AbstractHttpConfigurer::disable)
            
            // 2. Stateless сессии: сервер не хранит состояние
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS)
            )
            
            // 3. Провайдер аутентификации (UserDetailsService + PasswordEncoder)
            .authenticationProvider(authenticationProvider())
            
            // 4. Добавляем JWT-фильтр ПЕРЕД стандартным фильтром логина
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            
            // 5. Правила доступа к URL
            .authorizeHttpRequests(auth -> auth
                
                // === ОТКРЫТЫЕ ЭНДПОИНТЫ (без токена) ===
                .requestMatchers("/api/auth/**").permitAll()
                .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()
                
                // === НАСТРОЙ ПОД СВОЙ ПРОЕКТ (примеры) ===
                // .requestMatchers(HttpMethod.GET, "/api/products/**").permitAll()
                // .requestMatchers(HttpMethod.POST, "/api/orders").hasAnyRole("USER", "ADMIN")
                // .requestMatchers("/api/admin/**").hasRole("ADMIN")
                
                // === ЗАКРЫТОЕ ПО УМОЛЧАНИЮ ===
                // Любые другие запросы требуют аутентификации
                .anyRequest().authenticated()
            );
        
        return http.build();
    }

    /*
     * authenticationProvider — настраивает, как проверять логин/пароль.
     * DaoAuthenticationProvider использует:
     *   - UserDetailsService для загрузки пользователя
     *   - PasswordEncoder для проверки пароля
     */
    @Bean
    public AuthenticationProvider authenticationProvider() {
        DaoAuthenticationProvider authProvider = new DaoAuthenticationProvider();
        authProvider.setUserDetailsService(userDetailsService);
        authProvider.setPasswordEncoder(passwordEncoder());
        return authProvider;
    }

    /*
     * authenticationManager — компонент для аутентификации.
       * Нужен в AuthService.authenticate() для проверки логина/пароля.
     */
    @Bean
    public AuthenticationManager authenticationManager(
            AuthenticationConfiguration config) throws Exception {
        return config.getAuthenticationManager();
    }

    /*
     * passwordEncoder — BCrypt для хэширования паролей.
     * BCrypt автоматически добавляет "соль" и делает хэш адаптивным.
     */
    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}

🌐 Шаг 11: AuthController (REST эндпоинты)

Контроллер принимает запросы на /api/auth/login и /api/auth/register. Валидация (@Valid) происходит автоматически.

security/AuthController.java
package com.example.employee.security;

import com.example.employee.security.dto.JwtResponse;
import com.example.employee.security.dto.LoginRequest;
import com.example.employee.security.dto.SignupRequest;
import com.example.employee.security.service.AuthService;
import jakarta.validation.Valid;
import lombok.RequiredArgsConstructor;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

/*
 * @RestController + @RequestMapping("/api/auth")
 * → Все методы возвращают JSON, базовый URL: /api/auth
 *
 * Примеры запросов:
 *   POST /api/auth/login    → аутентификация
 *   POST /api/auth/register → регистрация
 */
@RestController
@RequestMapping("/api/auth")
@RequiredArgsConstructor
public class AuthController {
    
    private final AuthService authService;

    /*
     * POST /api/auth/login
     *
     * Тело запроса (JSON):
     * {
     *   "username": "admin",
     *   "password": "admin123"
     * }
     *
     * Ответ (200 OK):
     * {
     *   "type": "Bearer",
     *   "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
     *   "id": 1,
     *   "username": "admin",
     *   "email": "admin@company.ru",
     *   "roles": ["ROLE_ADMIN"]
     * }
     *
     * @Valid — включает валидацию @NotBlank в LoginRequest
     * @RequestBody — Jackson парсит JSON → Java-объект
     */
    @PostMapping("/login")
    public ResponseEntity<JwtResponse> login(
            @Valid @RequestBody LoginRequest request) {
        return ResponseEntity.ok(authService.authenticate(request));
    }

    /*
     * POST /api/auth/register
     *
     * Тело запроса (JSON):
     * {
     *   "username": "newuser",
     *   "password": "strongpass123",
     *   "email": "user@example.com",
     *   "firstName": "Иван",
     *   "lastName": "Петров",
     *   "roles": ["ROLE_USER"]  // опционально
     * }
     *
     * Ответ (200 OK): "User registered successfully"
     *
     * Если username/email уже занят → 400 Bad Request
     * Если пароль короче 6 символов → 400 (валидация)
     */
    @PostMapping("/register")
    public ResponseEntity<?> register(
            @Valid @RequestBody SignupRequest request) {
        
        authService.register(request);
        return ResponseEntity.ok("User registered successfully");
    }
}

✅ Best & ⚠️ Anti Practices

✅ Best Practices
  • Храни JWT_SECRET в переменных окружения, не в коде
  • Используй @Transactional(readOnly = true) для SELECT
  • Внедряй зависимости через конструктор (@RequiredArgsConstructor)
  • Хэшируй пароли через BCryptPasswordEncoder
  • Проверяй уникальность username/email до сохранения
  • Используй Optional.orElseThrow() вместо null
  • Логируй ошибки валидации токена для отладки
⚠️ Antipatterns
  • ❌ Хранить пароли в открытом виде в БД
  • ❌ Использовать слабый секрет (<32 байт) для JWT
  • ❌ Возвращать UserDetails/Entity напрямую в JSON
  • ❌ Игнорировать валидацию (@Valid) на входящих DTO
  • ❌ Писать бизнес-логику в контроллере
  • ❌ Использовать new Service() вместо DI
  • ❌ Отключать @PrePersist для createdAt/updatedAt

❓ Вопросы для собеседования

Как работает аутентификация с JWT в Spring Security?
How does JWT authentication work in Spring Security?
Medium ▼
✅ Ответ
1) Клиент отправляет username/password на /api/auth/login. 2) AuthenticationManager проверяет учётные данные через UserDetailsService + PasswordEncoder. 3) При успехе JwtService генерирует подписанный токен с username и ролями. 4) Клиент сохраняет токен и отправляет его в заголовке Authorization: Bearer <token>. 5) JwtAuthenticationFilter перехватывает каждый запрос, валидирует токен и устанавливает аутентификацию в SecurityContext. 6) Spring Security проверяет права доступа через @PreAuthorize или конфигурацию SecurityFilterChain.
Зачем нужен UserDetails и почему нельзя использовать User-Entity напрямую?
Why do we need UserDetails? Why not use User entity directly?
Easy ▼
✅ Ответ
UserDetails — это интерфейс Spring Security, который определяет контракт для аутентификации: методы getUsername(), getPassword(), getAuthorities(), isEnabled() и т.д. Наша User-entity содержит бизнес-поля (email, firstName, createdAt), которые не нужны для аутентификации. UserDetailsImpl выступает адаптером: преобразует Set<Role> в Collection<GrantedAuthority>, скрывает пароль через @JsonIgnore, предоставляет стандартный интерфейс для Security.
Почему мы отключаем CSRF в SecurityConfig для JWT?
Why disable CSRF in SecurityConfig for JWT?
Medium ▼
✅ Ответ
CSRF (Cross-Site Request Forgery) защищает от атак, когда злоумышленник заставляет браузер жертвы отправить запрос на доверенный сайт. Защита основана на токенах в cookie. Но при JWT-аутентификации мы используем stateless сессии и передаём токен в заголовке Authorization, а не в cookie. Браузер не отправляет заголовки автоматически при переходе по ссылке, поэтому атаки CSRF невозможны. Отключение CSRF безопасно для API, но обязательно включай его для веб-приложений с cookie-сессиями.
Как обеспечить безопасность JWT-секрета в продакшене?
How to secure JWT secret in production?
Hard ▼
✅ Ответ
1) Никогда не храни секрет в коде — используй переменные окружения: ${JWT_SECRET:...}. 2) В Kubernetes используй Secrets, в Docker — .env файлы (добавь в .gitignore). 3) Используй менеджеры секретов: HashiCorp Vault, AWS Secrets Manager. 4) Регулярно ротируй секреты (раз в 90 дней). 5) Используй минимум 256-битный ключ для HS256. 6) В CI/CD передавай секреты через защищённые переменные (GitHub Actions Secrets, GitLab CI Variables). 7) Логируй попытки использования невалидных токенов для мониторинга атак.
В чём разница между @PreAuthorize и конфигурацией SecurityFilterChain?
Difference between @PreAuthorize and SecurityFilterChain config?
Hard ▼
✅ Ответ
SecurityFilterChain — глобальные правила доступа к URL (уровень маршрута). Пример: /api/admin/** требует ROLE_ADMIN. Работает до попадания в контроллер. @PreAuthorize — аннотация на уровне метода (бизнес-логика). Позволяет сложные выражения: @PreAuthorize("#userId == authentication.principal.id or hasRole('ADMIN')"). Используется, когда доступ зависит от данных, а не только от роли. Оба механизма дополняют друг друга: сначала проверяется URL, потом — метод.
